One Encoder Spec: a single source of truth

Every encoder variant is currently defined and re-referenced in eight places. This ADR collapses them into one canonical ENCODER_SPECS registry; every other site becomes a derivation.

The spec

{{ specCode }}

Two orthogonal axes: a small library of Readout classes owns all preparation polymorphically (point cloud at 37/64/dense, tokens global/full with max/mean pooling, pose, RGB), and four encoder kinds consume the result. The spec merely composes them. That is why the adapter and contract can be generic without becoming a flag-interpreter: everything variant-specific lives in Readout.prepare, so the adapter is a one-line fold over spec.readouts, and the contract resolves shapes at launch (readout-implied or probed from the first observation) and snapshots them — buffer, dummy input and Flax module all init from that one resolution. Encoder choice lives on the readout itself: each Readout class declares its legal kinds (RGB → cnn; point cloud → cnn/mlp; tokens → mlp/transformer) and carries the chosen one, validated at import time — an illegal pairing can never reach a launch. A hybrid is simply a spec with more than one readout; the branches fuse automatically.
