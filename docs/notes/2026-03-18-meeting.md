## Discussion Points

### 1. Incorporating Current Observations into the World Model

It is important to include the current observation in the model. Two architectural options were discussed:

| Option | Description |
|--------|-------------|
| **Posterior integration** | Feed current observations into the posterior (recognition model), so the latent state is directly conditioned on the current obs |
| **Fusion module** | Add a separate fusion module that combines current observations with the latent state |

**Open:** Which option better preserves 3D information while keeping the world model dynamics stable?

### 2. VGGT Inference Frequency

Should the VGGT encoder run at **every time step** or only at selected steps (e.g., every N steps)?

- Every step: richer 3D features but computationally expensive
- Periodic: cheaper, but the world model must bridge gaps between VGGT updates

### 3. Observation Handling: Keep or Replace

Discussion on whether to **retain previous observations** across steps or **replace them entirely** with new observations at each step.

- Retaining: accumulates context over time, potentially better scene understanding
- Replacing: avoids stale information, simpler memory management

### 4. Environment Complexity

Discussion on which environments to use for evaluation. Consensus that it makes sense to use **complex environments** — simpler environments may not sufficiently challenge the world model and would make it harder to demonstrate the benefit of 3D scene understanding.
