Step 1

The Reinforcement Learning Problem

The Agent-Environment Loop

An agent interacts with an environment in discrete time steps. At each step:

  • The agent observes the current state \(s_t\)
  • The agent selects an action \(a_t\) according to its policy \(\pi(a_t \mid s_t)\)
  • The environment returns a reward \(r_t\) and the next state \(s_{t+1}\)
  • The agent's goal: maximize the cumulative discounted reward (return)
$$G_t = \sum_{k=0}^{\infty} \gamma^k r_{t+k}$$

where \(\gamma \in [0,1)\) is the discount factor that makes the agent prefer sooner rewards.

Key idea: The agent does not know the rules of the environment. It must learn a good policy from experience, by trial and error. This is the fundamental RL problem. The question is: how should the agent learn?

Step 2

Model-Free RL: Learning from Experience

The Direct Approach: Policy Gradient

The simplest idea: try actions in the real environment, observe which ones lead to high reward, and do more of those.

  • REINFORCE (Williams, 1992): the foundational policy gradient algorithm
  • If an action led to high reward, increase its probability
  • If an action led to low reward, decrease its probability
$$\nabla_\theta J(\theta) = \mathbb{E}\big[G_t \cdot \nabla_\theta \log \pi_\theta(a_t \mid s_t)\big]$$

"Move the policy in the direction that makes high-return actions more likely."

The Problem: High Variance

REINFORCE works in theory, but individual updates are very noisy:

  • A single trajectory might get lucky or unlucky
  • The return \(G_t\) includes all future rewards, making it hard to tell which action was actually good
  • Sparse rewards make this worse: most trajectories get zero signal
  • Needs many real environment interactions to converge
Analogy: Imagine learning to cook by making a full meal, tasting the result, then adjusting every step of the recipe equally. You cannot tell which step made it bad.
Next question: Can we reduce this variance by having a second network that estimates how good each state is, so we can evaluate individual actions rather than entire trajectories? This leads to actor-critic methods.

Step 3

Actor-Critic: Two Networks, One Goal

The Actor (Policy Network)

Decides what to do. Maps states to actions.

  • Input: current state \(s_t\)
  • Output: probability distribution over actions \(\pi_\theta(a \mid s_t)\)
  • Updated via policy gradient (REINFORCE)

The Critic (Value Network)

Judges how good a state is. Predicts future return.

  • Input: current state \(s_t\)
  • Output: estimated return \(v_\psi(s_t) \approx \mathbb{E}[G_t \mid s_t]\)
  • Provides the baseline for the actor

Advantage = Actual - Expected

$$\text{advantage} = \underbrace{G_t}_{\text{actual return}} - \underbrace{v_\psi(s_t)}_{\text{critic baseline}}$$
  • Positive: action was better than expected, reinforce it
  • Negative: action was worse than expected, discourage it
Limitation: Both actor and critic still learn from real environment interactions. Every training step requires an actual step in the environment. Can we do better?

Step 4

World Models: Learning to Dream

The Key Insight

What if the agent could learn the rules of the environment and then practice inside its own head?

  • A world model predicts: "if I do action \(a_t\) in state \(s_t\), what happens next?"
  • Once learned, the agent imagines trajectories without touching the real environment
  • The actor-critic trains on imagined experience

Model-Free vs. Model-Based

Historical context: The idea of learning a model and planning inside it goes back to Sutton's Dyna architecture (1991). Ha & Schmidhuber (2018) popularized the term "World Models" by showing agents could learn environment dynamics as a latent space and train controllers entirely in imagination. DreamerV3 is the modern culmination of this line of work.

Step 5

DreamerV3: All Pieces Connected

DreamerV3 combines the agent-environment loop, actor-critic, and world model into one integrated system.

For this repo's VGGT/R2Dreamer encoder and replay topology, see architecture-data-flow.html.

The Complete Training Loop

Phase 1: Acting in the Real Environment
Agent observes \(s_t\)
→
Actor picks \(a_t\)
→
Environment returns \(s_{t+1}, r_t\)
→
Store in Replay Buffer

Full episodes (up to 500 steps). This is the classic RL loop from Slide 2.

Phase 2: Training the World Model
Sample 64-step windows
→
Encode observations
→
Learn transitions + rewards
→
Reconstruct observations

Learns local dynamics from short windows, not full episodes. 64 steps is enough for step-by-step transitions.

Phase 3: Actor-Critic in Imagination
Pick starting states
→
Imagine 15 steps forward
→
Critic evaluates returns
→
Actor improves policy

No real environment needed. The actor-critic from Slide 4 now trains entirely in the world model's imagination.

Why this is powerful: One real environment step produces training data for the world model, which then generates unlimited imagined experience for the actor-critic. The agent "practices in its head" rather than wasting real environment interactions. This makes DreamerV3 extremely sample-efficient.

Motivation

Why DreamerV3?

The Problem with RL Today

  • Specialized algorithms tuned per domain
  • Hyperparameter tuning requires expertise + compute
  • Algorithms that work on Atari fail on robotics
  • Sparse rewards break most methods
  • Signal magnitudes vary by orders of magnitude

DreamerV3's Promise

  • One set of hyperparameters for all domains
  • Continuous and discrete action spaces
  • Dense and sparse rewards
  • Visual (pixels) and low-dimensional inputs
  • 2D and 3D environments
Core idea: Learn a world model, then train the policy entirely inside that model via imagined rollouts. Robustness techniques (symlog, return normalization, free bits) make this work across domains without tuning.

Architecture

Three Neural Networks

This is the generic DreamerV3 architecture. The current project-specific data flow is centralized in the global architecture page.

1. World Model (RSSM)

Learns a compact latent representation of the environment via autoencoding. Predicts future states, rewards, and episode termination.

  • Trained on real experience from replay buffer
  • Encoder: image/vector → latent
  • Decoder: latent → reconstruction
  • Predicts: rewards, continuation flags

2. Critic

Learns to predict the distribution of future returns from any model state. Uses distributional RL (not just mean).

  • Trained on imagined trajectories
  • Categorical distribution over symexp bins
  • EMA-regularized for stability
  • Provides baseline for actor

3. Actor

Selects actions to maximize return, trained purely from imagined rollouts. Uses REINFORCE with entropy bonus.

  • Trained on imagined trajectories
  • Works for discrete + continuous actions
  • Return-normalized advantage
  • Fixed entropy scale across all domains
Training loop: Collect experience → train world model on replayed data → imagine trajectories in model → train actor + critic on imagined data → repeat.

World Model

Recurrent State-Space Model (RSSM)

Model State: \(s_t = \{h_t, z_t\}\)

Each state has two parts:

  • \(h_t\) — deterministic recurrent state (GRU hidden state, captures history)
  • \(z_t\) — stochastic discrete representation (32 categoricals with 32 classes each)

RSSM Components

Sequence model\(h_t = f_\phi(h_{t-1}, z_{t-1}, a_{t-1})\)
Encoder\(z_t \sim q_\phi(z_t \mid h_t, x_t)\)
Dynamics predictor\(\hat{z}_t \sim p_\phi(\hat{z}_t \mid h_t)\)
Reward predictor\(\hat{r}_t \sim p_\phi(\hat{r}_t \mid h_t, z_t)\)
Continue predictor\(\hat{c}_t \sim p_\phi(\hat{c}_t \mid h_t, z_t)\)
Decoder\(\hat{x}_t \sim p_\phi(\hat{x}_t \mid h_t, z_t)\)

World Model Loss

$$\mathcal{L}(\phi) = \mathbb{E}_{q_\phi}\Big[\sum_{t=1}^{T}(\beta_\text{pred}\mathcal{L}_\text{pred} + \beta_\text{dyn}\mathcal{L}_\text{dyn} + \beta_\text{rep}\mathcal{L}_\text{rep})\Big]$$
  • Prediction loss — reconstruct observations, rewards, continuation
  • Dynamics loss — KL(encoder || prior), train predictor
  • Representation loss — KL(encoder || prior), train encoder

Key Design Choices

  • Discrete latents (32 x 32 categoricals) — combinatorial expressiveness
  • Free bits — clip KL below 1 nat to avoid trivially small representations
  • 1% unimix — mix 99% network + 1% uniform to prevent zero probabilities
  • Separate stop-gradients on dynamics vs. representation losses to balance learning

Training

Two-Phase Training Loop

Phase A: World Model Learning

Train on real experience from the replay buffer.

  • Batch: 16 sequences x 64 timesteps
  • Online queue with latent state caching
  • Reconstruction gradients shape representations

  • Start from states encountered during world model training
  • Roll out T=16 imagined steps
  • Compute \(\lambda\)-returns from predicted rewards
  • No real environment interaction needed
Why this works: The world model provides unlimited synthetic experience for free. The actor can explore thousands of strategies in imagination without spending a single real environment step. This makes DreamerV3 extremely sample-efficient.

Actor-Critic

Policy & Value Learning

Actor Loss (REINFORCE)

$$\mathcal{L}(\theta) = -\sum_{t=1}^{T-1} \text{sg}\!\Big(\frac{R_t^\lambda - v_\psi(s_t)}{\max(1, S)}\Big) \cdot \log \pi_\theta(a_t \mid s_t) + \eta\, H[\pi_\theta]$$
  • Advantage: \(R_t^\lambda - v_\psi(s_t)\) with stop-gradient
  • Return normalization S: EMA of 5th–95th percentile range
  • Denominator clamp: \(\max(1, S)\) — only scales down, never amplifies noise
  • Entropy bonus: fixed \(\eta = 3 \times 10^{-4}\) across all domains

Why REINFORCE over Reparameterization?

  • Works for both discrete and continuous actions
  • Same code path regardless of action space
  • Combined with return normalization, produces stable gradients

Critic Loss (Distributional)

$$\mathcal{L}(\psi) = -\sum_{t=1}^{T} \ln p_\psi(R_t^\lambda \mid s_t)$$
  • Predicts the distribution of returns, not just the mean
  • Categorical over exponentially spaced bins (symexp)
  • Handles multi-modal return distributions
  • Decouples gradient scale from target magnitude

\(\lambda\)-Returns

$$R_t^\lambda = r_t + \gamma c_t \big((1-\lambda) v_t + \lambda R_{t+1}^\lambda\big)$$
  • \(\gamma = 0.997\), \(\lambda = 0.95\)
  • Continuation flag \(c_t\) handles episode boundaries
  • Bootstraps from critic at horizon \(T=16\)

Key Innovation

Robustness Techniques

These techniques enable fixed hyperparameters across all domains

Symlog & Symexp Predictions

$$\text{symlog}(x) = \text{sign}(x) \ln(|x|+1)$$ $$\text{symexp}(x) = \text{sign}(x)(\exp(|x|)-1)$$
  • Compresses large magnitudes, preserves sign
  • Identity near origin — small targets unaffected
  • Applied to observations, rewards, and returns
  • Decouples gradient magnitude from target magnitude

Symexp Twohot Loss

$$\hat{y} = \text{softmax}(f(x))^T B,\quad B = \text{symexp}([-20\ldots+20])$$
  • Predict continuous values via categorical distribution
  • Bins exponentially spaced via symexp
  • Twohot encoding: soft target across 2 nearest bins
  • Used for reward predictor and critic

Return Normalization

$$S = \text{EMA}\big(\text{Per}(R^\lambda, 95) - \text{Per}(R^\lambda, 5),\; 0.99\big)$$
  • Normalizes returns to ~[0, 1] regardless of reward scale
  • Percentile-based, robust to outliers
  • \(\max(1, S)\) clamp: never amplifies small signals
  • Fixes sparse reward failure mode of std normalization

KL Balancing & Free Bits

  • Free bits: clip KL below 1 nat to focus learning on prediction loss when representations are already informative
  • KL balancing: separate stop-gradients — dynamics loss trains the predictor, representation loss trains the encoder
  • 1% unimix: prevents zero probabilities in categoricals, ensures well-behaved KL

Core Challenge

Handling Sparse & Dense Rewards

The Problem

Reward scales vary by orders of magnitude across domains:

DomainReward TypeScale
AtariDenseScores in 100s–10,000s
Proprio ControlDenseSmall continuous values
BSuiteMixedBinary to continuous
MinecraftVery sparseSingle +1 after 1000s of steps

Standard approach: normalize by standard deviation. But under sparse rewards, std ≈ 0, which amplifies random noise and stagnates learning.

DreamerV3's Solution: 5 Interlocking Mechanisms

No single trick — a system of techniques that work together:

  • 1. Percentile return normalization with clamp
  • 2. Symexp twohot for critic & reward predictor
  • 3. Symlog observation compression
  • 4. Fixed entropy bonus
  • 5. World model provides dense signal always

1. Return Normalization (Key Mechanism)

$$\text{advantage} = \frac{R_t^\lambda - v(s_t)}{\max(1,\; S)}$$ $$S = \text{EMA}(\text{Per}_{95} - \text{Per}_{5})$$
  • Dense (S >> 1): divides returns down to ~[0,1], prevents gradient explosion
  • Sparse (S < 1): clamp kicks in, advantage passed untouched — never amplifies noise
  • Percentile-based, not std-based — robust to outliers

2. Symexp Twohot Critic

Critic predicts a categorical distribution over exponentially spaced bins, not a scalar.

  • Reward of 10,000 → same gradient scale as 0.01
  • Multi-modal distributions (mostly 0, occasionally large) handled naturally
  • Decouples gradient magnitude from target magnitude

3–5. Supporting Mechanisms

  • Symlog: compresses large observations, identity near zero — same network handles both scales
  • Fixed entropy \(\eta = 3\!\times\!10^{-4}\): consistent exploration pressure. Dense rewards don't overwhelm it; sparse rewards don't let it dominate
  • Reconstruction loss: world model gets dense learning signal from pixels at every timestep, even with zero reward — builds good representations before any reward is seen
Why this matters for Minecraft: The agent must discover 12 items in a crafting tree with only sparse +1 signals. The world model learns environment dynamics from pixels (dense signal), while \(\max(1, S)\) ensures the rare reward signals aren't drowned in noise. Previous methods needed human demonstrations or curricula.

Default: 200M (12M for control suites). All hyperparameters fixed across sizes.

Network Components

  • Encoder/Decoder: stride-2 CNNs (images) or 3-layer MLPs (vectors)
  • Sequence model: Block-diagonal GRU (8 blocks) — scales without quadratic cost
  • Actor & Critic: 3-layer MLPs
  • Predictors: 1-layer MLPs (reward, continue)
  • Optimizer: LaProp with AGC (adaptive gradient clipping)

Scaling Properties

  • Performance increases monotonically with model size
  • Larger models are also more sample-efficient
  • Higher replay ratios increase data efficiency predictably
  • All sizes trained on a single A100 GPU

Replay Buffer

  • Uniform replay (no prioritized replay)
  • Online queue: new data enters immediately
  • Stores latent states, not raw observations
  • Replay ratio controls compute/data trade-off
  • Default ratio: 32 (Atari, DMLab, ProcGen)
Key insight: Performance rests on the unsupervised reconstruction loss — not on reward/value prediction gradients. This is unlike most prior model-based RL.
