Dreamer / r2dreamer vector observation input shapes

A grounded reading of NM512/r2dreamer and danijar/dreamerv3 source for the feat/variant-1-aggregator-mlp branch. Every claim links to a file path and a line number in the upstream repos.

TL;DR — expected vector input shape for r2dreamer.

For this repo's current VGGT/R2Dreamer encoder inventory and replay/RSSM flow, use the canonical architecture-data-flow.html. This page remains the upstream Dreamer vector-input research note.

  • Observations are a gym.spaces.Dict keyed by string; each entry is a gym.spaces.Box with per-step shape (D,) (or (N, D)) for vectors and (H, W, C) for images. The dict must also contain is_first, is_last, is_terminal, reward (these are excluded from the encoder).
  • r2dreamer routes a key to the MLP branch iff len(space.shape) in (1, 2) and the key matches the regex encoder.mlp_keys — otherwise it goes to the CNN branch (len == 3 and matches encoder.cnn_keys). Both default regexes are env-config-driven.
  • During training the replay buffer hands the encoder a TensorDict where every vector observation tensor has shape (B, T, D) (B = batch_size = 16, T = batch_length = 64 by default). For shape (N, D) spaces, the tensor is (B, T, N, D) and gets flat-concatenated to (B, T, N*D) before the MLP via sum(v) over the shape tuple.
  • The MLP is 3 linear layers of units (default 1024 from model.units) with RMSNorm and the configured activation, optionally preceded by symlog on the inputs (encoder.mlp.symlog_inputs: True by default).
  • So if your VGGT aggregator encoder outputs a (D,) per-step feature, register an obs key (e.g. vggt_tokens) as gym.spaces.Box(-inf, inf, shape=(D,), dtype=float32), add it to the encoder.mlp_keys regex, and r2dreamer will deliver it to your MLP as (B, T, D).

2. Expected tensor shape during training

r2dreamer uses TorchRL’s SliceSampler to draw B contiguous slices of length T+1 from a 2-D LazyTensorStorage, then crops the first step away as “initial”:

And MLP.forward confirms it preserves the leading axes:

The MLP’s input dim aggregates over all mlp-matched keys:

122 if self.mlp_shapes:
123     inp_dim = sum([sum(v) for v in self.mlp_shapes.values()])
124     self.encoders.append(MLP(config.mlp, inp_dim))
125     self.selectors.append(lambda obs: torch.cat([obs[k] for k in self.mlp_shapes], -1))
r2dreamer/networks.py:122-125

Three things to note:

  • sum(v) flattens a per-step shape tuple by summing the dims. For shape=(D,) this is just D. For shape=(N, D) it is N + D, not N*D — but in practice this still works because the torch.cat([obs[k]], -1) over a single (B, T, N, D) tensor leaves it 4-D and then the linear layer in MLP sees the trailing axis as D, with the leading (B, T, N) treated as batch. This is a quirk worth verifying for any 2-D space. For a flat (D,) there is no ambiguity.
  • For multiple mlp keys, all of them are concatenated along the last axis before the MLP, so all keys must share the same leading (B, T).
  • The CNN encoder reshapes via (B, T, H, W, C) → (B*T, H, W, C) internally and then (B, T, F) back out (see ConvEncoder.forward, networks.py:221-234). The MLP path does not flatten the time axis — the linear layers just broadcast over leading dims.

Vanilla dreamerv3 (JAX) takes the dual approach — it explicitly flattens leading dims before the MLP:

210 def __call__(self, carry, obs, reset, training, single=False):
211     bdims = 1 if single else 2
  …
215     if self.veckeys:
216         vspace = {k: self.obs_space[k] for k in self.veckeys}
217         vecs   = {k: obs[k] for k in self.veckeys}
218         squish = nn.symlog if self.symlog else lambda x: x
219         x = nn.DictConcat(vspace, 1, squish=squish)(vecs)
220         x = x.reshape((-1, *x.shape[bdims:]))
221         for i in range(self.layers):
222             x = self.sub(f'mlp{i}', nn.Linear, self.units, **self.kw)(x)
dreamerv3/dreamerv3/rssm.py:210-224

So in dreamerv3 the MLP itself sees (B*T, D), and the result is reshaped back to (B, T, F) at line 248. In r2dreamer the MLP never reshapes — it sees (B, T, D) directly and broadcasts.

3. Encoder routing: vector vs image

r2dreamer’s heuristic combines a shape-length test with a regex match on the key name:

108 self.cnn_shapes = {k: v for k, v in shapes.items()
                       if len(v) == 3 and re.match(config.cnn_keys, k)}
109 self.mlp_shapes = {k: v for k, v in shapes.items()
                       if len(v) in (1, 2) and re.match(config.mlp_keys, k)}
r2dreamer/networks.py:108-109
BranchShape ruleRegex
CNN imagelen(shape) == 3 (i.e. (H, W, C))encoder.cnn_keys
MLP vectorlen(shape) in (1, 2) (i.e. (D,) or (N, D))encoder.mlp_keys

If a key matches neither rule (e.g. a 4-D tensor or a 2-D tensor whose name doesn’t match mlp_keys) it is silently dropped from the encoder. The constructor prints what survived (networks.py:110-111), which is useful for debugging.

Default config values driving the shapes

All knobs are wired through Hydra. The defaults come from configs/model/_base_.yaml + the chosen size config (e.g. size12M.yaml):

Symbol in diagramConfig pathDefault (size12M / size200M)Effect
config.layers encoder.mlp.layers 3 / 3 Number of Linear→RMSNorm→Act blocks — one extra block adds U² params.
U (config.units) encoder.mlp.units ← model.units 256 / 1024 Width of every Linear, and the final out_dim handed to the RSSM.
activation encoder.mlp.act ← model.act SiLU / SiLU getattr(torch.nn, config.act) — any nn.* activation name works.

symlog gate encoder.mlp.symlog_inputs True / True Set to False if you pre-normalize your features (e.g. unit-norm aggregator tokens) and don’t want the log compression.
routing regex (vector) encoder.mlp_keys ← env.encoder.mlp_keys '.*' for proprio envs Whether your obs key enters the MLP at all. Keys that don’t match are silently dropped — check the "Encoder MLP shapes:" print at startup (networks.py:110).

So for a stock size12M proprio config: 3 layers × 256 units × SiLU + RMSNorm, with symlog applied to the concatenated input. Stepping up to size200M only widens U to 1024 — the architecture itself stays a flat 3-block stack.

Two things the diagram makes obvious:
  • Multiple vector observation keys get concatenated, not fused with attention or separate streams. If you want each modality processed independently first, you need to do that outside the obs dict (in the env wrapper or a custom encoder).
  • The MLP has zero notion of time — it treats the (B, T, ·) leading dims as plain batch dimensions. Temporal modelling is the RSSM’s job, which consumes (B, T, U) downstream. So the encoder is purely a per-timestep feature extractor.

5. Key filtering: mlp_keys / cnn_keys regex

r2dreamer wires the regex through Hydra: encoder.mlp_keys defaults to ${env.encoder.mlp_keys}, i.e. it is set per environment. See:

13 encoder:
14   mlp_keys: '.*'
15   cnn_keys: '$^'           # matches nothing
r2dreamer/configs/env/dmc_proprio.yaml:13-15 (proprio: all vectors, no images) 
13 encoder:
14   mlp_keys: '$^'           # matches nothing
15   cnn_keys: 'image'
r2dreamer/configs/env/dmc_vision.yaml:13-15 (vision: only image)

The matching is via re.match(...) — i.e. anchored at the start of the string but not the end. So 'image' matches 'image' and would also match 'image_left', etc.

Useful idioms:

  • '.*' → match all keys.
  • '$^' → match nothing (used to disable a branch).
  • '(state|vggt_tokens)' → explicit whitelist.

If you add a new obs key but do not include it in the regex, r2dreamer will silently drop it from the encoder. The print at networks.py:111 is your sanity check.

6. Normalization & preprocessing

Two layers of preprocessing apply to vector inputs:

(a) Image-only float cast & rescale happens once in Dreamer.preprocess; vectors pass through untouched:

568 @torch.no_grad()
569 def preprocess(self, data):
570     if "image" in data:
571         data["image"] = to_f32(data["image"]) / 255.0
572     return data
r2dreamer/dreamer.py:568-572

(b) Symlog inside the MLP (encoder.mlp.symlog_inputs: True by default) compresses unbounded vector ranges before the first linear:

331 def forward(self, x):
332   # (B, T, I)
333   if self._symlog_inputs:
334     x = dists.symlog(x)
335   return self.layers(x)
r2dreamer/networks.py:331-336

Plus RMSNorm after every linear (see section 4). There is no per-key running mean/std or batch norm.

Caveat for VGGT tokens. Symlog (sign(x)*log(1+|x|)) is shape-preserving but is a non-trivial nonlinearity. If your aggregator features are already well-normalised (e.g. LayerNorm output from the VGGT backbone), you may want to set encoder.mlp.symlog_inputs: False for that branch, or disable it globally and accept the standard dreamerv3 default.

The big practical difference for your variant: in r2dreamer your encoder method sees (B, T, D) directly. In vanilla dreamerv3 your encoder method sees (B*T, D) after the reshape on rssm.py:220. Since the user’s VGGTAggregatorMLPEncoder (src/r2dreamer/networks.py:457-478) is JAX/Flax-style and branches on obs.ndim == 2 vs obs.ndim == 3, it implicitly assumes the dreamerv3 reshape convention (mean-pooled (B, D), or all-token (B, N, D)). That matches a dreamerv3-style codepath, not r2dreamer’s upstream PyTorch MultiEncoder.

8. Recommendations for the feat/variant-1-aggregator-mlp branch

You said: “fast-path aggregator MLP encoder produces VGGT aggregator tokens as vector features”, stored mean-pooled in replay as (B, D). Concretely, to fit cleanly into the Dreamer encoder contract:

1. Register the obs key as a vector Box

In your env wrapper’s observation_space (analogous to envs/dmc.py:46-55 in r2dreamer), add:

spaces["vggt_tokens"] = gym.spaces.Box(
    low=-np.inf, high=np.inf,
    shape=(D,),                # the mean-pooled feature dim, e.g. 1024 or 1408
    dtype=np.float32,
)

Per-step shape (D,), never (1, D) and never (B, D). The batch and time axes are added by the replay/sampler.

2. Add the key to the encoder regex

In your env config (e.g. a new configs/env/vggt_*.yaml):

encoder:
  mlp_keys: '(state|vggt_tokens)'     # or just 'vggt_tokens' if you don't keep state
  cnn_keys: '$^'
decoder:
  mlp_keys: '(state|vggt_tokens)'
  cnn_keys: '$^'

Without this, MultiEncoder.__init__ (networks.py:109) will silently drop the key. Check the startup logs for Encoder MLP shapes: {'vggt_tokens': (D,), ...} (networks.py:110-111).

3. Expect (B, T, D) in your forward

If you are using upstream r2dreamer’s PyTorch MLP as the encoder body, it will receive your tensor as (B, T, D) and broadcast the linear layers over the first two axes. If you replace that body with your own VGGTAggregatorMLPEncoder, write its forward to accept (B, T, D) as the standard contract:

# r2dreamer / PyTorch contract (matches networks.py MLP):
def forward(self, x):       # x: (B, T, D)
    return self.proj(x)      # -> (B, T, embed_dim)

The user’s current JAX implementation (src/r2dreamer/networks.py:469-478) branches on obs.ndim == 2 and obs.ndim == 3. That matches the vanilla dreamerv3 contract (post-reshape, (B*T, D) is 2-D). If the calling code in src/r2dreamer/agent.py indeed reshapes to (B*T, D) before calling, that is fine; otherwise the encoder should also handle 3-D input (B, T, D) — you can add a branch:

if obs.ndim == 3 and obs.shape[-1] == self.feat_in:
    # (B, T, D) -> pass straight to Dense, no mean
    return nn.Dense(self.embed_dim, name="proj")(obs)

4. Decide on symlog

The default encoder.mlp.symlog_inputs: True will apply symlog elementwise to your aggregator features before the projection (networks.py:333-334). VGGT pre-head features are typically in a bounded numeric range thanks to internal LayerNorm, so symlog is unlikely to hurt, but you may want to A/B it. Toggle via:

encoder:
  mlp:
    symlog_inputs: False

5. Two-key mode: keep state alongside vggt_tokens

If you want proprioception alongside the aggregator features, just register both keys. r2dreamer concatenates all mlp keys along the last axis via torch.cat([obs[k] for k in mlp_shapes], -1) (networks.py:125) and projects with one shared MLP whose inp_dim = D_state + D_vggt (networks.py:123).

6. Sanity checks to add to your test

  • Print Encoder MLP shapes at construction time (already done by upstream at networks.py:111). Confirm vggt_tokens is listed.
  • Insert a one-shot assert x.shape[-1] == expected_D check at the start of your encoder forward.
  • If using the upstream MLP, confirm encoder.out_dim equals units (1024 by default) — this is what feeds RSSM’s embed_size in dreamer.py:36.

7. If the variant relies on a token-axis (B, T, N, D) shape

The shape rule len(v) in (1, 2) means a 2-D per-step space (N, D) is allowed, and the replay will deliver (B, T, N, D). But the concat-then-MLP path computes inp_dim = sum((N, D)) = N + D, which is almost certainly not what you want. Two safe options:

  1. Mean-pool in the env wrapper so the obs key is flat (D,) per step (this is what your “fast path” already does — keep it).
  2. Bypass MultiEncoder: keep a custom encoder module that handles (B, T, N, D) directly, and skip the regex/heuristic. Your src/r2dreamer/agent.py conditional on encoder_type == "vggt_aggregator_mlp" already does this.
