Simple RL Baselines for World-Model Evaluation

6 options: 5 that exercise the world model directly, plus a model-free reference (PPO) for sample-efficiency comparison.

Compiled 2026-05-06 · for thesis world-model evaluation

Why move beyond random?

A random policy wanders. It only stress-tests the world model on the dynamics of aimless trajectories. The interesting question — does the model predict correctly along reward-relevant trajectories? — needs a policy that tries. Each baseline below exposes a different failure mode of the learned model.

01

Random Shooting MPC (RS)

planning easy · ~50 LoC no training

Sample N action sequences, score each by rolling out through the world model, execute the first action of the best one. Receding horizon.

Why better than random
Directly uses the world model to act, so trajectories concentrate where the model claims reward is high. If the model is wrong, divergence in the real env becomes immediately visible.
Hyperparameters
N ≈ 500–2000 candidates · H ≈ 10–30 horizon · uniform action sampling
When it's the right pick
Canonical first model-based baseline. Exposes exploitation bias — regions where the model is overoptimistic about reward.
Nagabandi et al. 2017 (paper) MBRL benchmarking notes
02

Cross-Entropy Method MPC (CEM)

planning easy · ~80 LoC no training

Same MPC loop as RS, but instead of uniform sampling, fit a Gaussian over actions, take top-k elites, refit, repeat. The planner inside PETS and PlaNet.

Why better than random
Concentrates samples on high-reward action sequences faster than RS. Pushes the world model along narrow, near-optimal trajectories — exactly the regime where overconfidence hurts most.
Hyperparameters
pop ≈ 100–500 · elites ≈ 10% · iters ≈ 3–5 · horizon H · initial variance
When it's the right pick
When RS is too sparse to find good trajectories within budget. Standard baseline in any modern world-model paper. Exposes overconfidence on the optimal manifold.
Chua et al. 2018 — PETS (paper) Reference code iCEM improvements
03

Dyna-Q

learned policy easy · ~100 LoC tabular or NN

Q-learning where each real transition triggers k extra Q-updates from simulated transitions sampled from the learned model. Sutton's original integrated planning + learning architecture.

Why better than random
Produces a learned policy from world-model rollouts. Any bias in the model directly poisons the policy — and the gap between model-trained-policy behavior in the model vs. the real env is exactly what you want to measure.
Hyperparameters
α learning rate · γ discount · ε-greedy · k ≈ 5–50 planning steps
When it's the right pick
Discrete or low-dim envs. Cleanest separation of "model error" vs. "RL algorithm complexity" — almost no moving parts. Exposes compounding rollout error: k-step simulated updates magnify model bias.
Sutton & Barto Ch. 8 Reference notebook
04

REINFORCE with value baseline

learned policy medium · ~150 LoC continuous OK

Vanilla Monte-Carlo policy gradient. Sample episodes, compute returns, subtract a learned value baseline, gradient-ascend on log-prob × advantage.

Why better than random
Continuous-action capable, single small MLP, fully learned policy. Two clean evaluation protocols: (a) train inside the world model, deploy in real env → measures whether the model supports policy improvement; (b) train in real env, roll out in model → measures fidelity on competent trajectories.
Hyperparameters
lr · γ · episode batch size · entropy coefficient (optional)
When it's the right pick
You want a learned-policy companion to the planning baselines without PPO's clip/GAE/minibatch machinery. Exposes whether the world model supports gradient-based policy improvement, not just planning.
HuggingFace PyTorch tutorial Reference repo rl-book chapter
05

DQN (off-the-shelf via Stable-Baselines3)

learned policy trivial · ~5 LoC w/ SB3 discrete only

Deep Q-learning with replay buffer + target net. DQN("MlpPolicy", env).learn(10_000) — five lines and you have a competent baseline.

Why better than random
Mature, well-tested. Train it on the world model's simulated transitions and evaluate in the real env (classic Dyna-style eval); the gap reveals where the model's predicted Q-landscape misaligns with reality.
Hyperparameters
lr ≈ 1e-3 · buffer size · batch ≈ 64 · target update freq · ε-decay schedule
When it's the right pick
Discrete-action envs where you want a "real" model-free RL baseline as an upper-bound reference, without writing it yourself. Exposes value-function distortion in the world model.
SB3 DQN docs Pretrained CartPole DQN
06

PPO (off-the-shelf via SBX, JAX)

model-free reference trivial · ~10 LoC w/ SBX discrete + image obs

Proximal Policy Optimization, on-policy, JAX-jitted via Stable-Baselines Jax (SBX). PPO("CnnPolicy", env).learn(N) — same API as SB3, but JAX backend matches the rest of the stack.

Why this baseline
Different role from Options 1–5: PPO does not probe the world model. It's the model-free reference point — train PPO on the real env at the same env-step budget as DreamerV3, and the gap (or its absence) tells you whether the world model is buying anything. The headline "world models are sample-efficient" claim only holds if DreamerV3-3D beats PPO at matched frames.
Hyperparameters
n_steps ≈ 128–2048 · batch_size ≈ 64 · n_epochs ≈ 4–10 · γ ≈ 0.99 · clip_range ≈ 0.2 · ent_coef ≈ 0.0–0.01 · VecFrameStack(k=4) as memory proxy
When it's the right pick
You need a credible model-free reference for sample-efficiency curves and reviewers will expect one. SBX keeps you on JAX (no PyTorch for one baseline), supports discrete actions and CNN policies out of the box, and inherits SB3's EvalCallback / W&B integration so curves overlay your DreamerV3 runs cleanly.
Caveat
Neither SBX nor SB3 ships recurrent PPO. ObjectNav is a POMDP — feed-forward PPO with frame-stacking will plateau below DD-PPO+LSTM (the Habitat-lab gold standard). Document this gap; the comparison is still meaningful as long as DreamerV3 is also evaluated without external recurrence.
SBX repo SB3 PPO docs (same API) DD-PPO / Habitat ObjectNav reference

Recommended minimal set for the thesis

Pick one from each row — they expose distinct failure modes, so running all three gives a much richer picture than running three variants of the same idea.

  • 🎯 Planning, no training: Random Shooting (Option 1). Trivial; gives you the "does planning through the model work at all?" signal.
  • 🔬 Stronger planner: CEM-MPC (Option 2). Same code shape as RS, exposes a different failure mode.
  • 🧠 Learned policy: REINFORCE (Option 4). Tests whether the model's gradient signal is usable for policy improvement.
  • 📐 External reference: PPO via SBX (Option 6). Not a WM probe — the model-free reference that makes the sample-efficiency claim falsifiable.

If you only have time for one upgrade over random, start with Random Shooting MPC — it's the cheapest meaningful baseline in the entire model-based RL literature. Add PPO (SBX) when you're ready to publish — reviewers will ask for a model-free reference even if WM probes are strong.
