Using CNNs on 3D Point Clouds (XYZ data)

Web search summary · May 2026 · scope: how convolutional architectures consume raw (x,y,z) point clouds, the main families of approaches, and trade-offs.

The core problem

A 3D point cloud is a set of points represented by their XYZ coordinates (optionally augmented with normals, RGB, intensity, etc.). Standard 2D CNNs assume a regular pixel grid; a point cloud is sparse, unordered, and irregularly sampled, so a vanilla convolution cannot be applied directly.

Three families of approaches dominate the literature: (1) voxelize then 3D-CNN, (2) operate directly on points (PointNet family), and (3) treat the cloud as a graph. Hybrid point–voxel methods are the current accuracy/efficiency sweet spot.

The three families + hybrid

1. Voxel-grid + 3D CNN

VoxNet, OctNet, MinkowskiNet, SECOND

Quantize space into a 3D grid, treat each occupied voxel as a sample, run 3D convolutions just like a 2D CNN but with one extra dimension.

Reuses the full CNN toolkit (strided conv, pooling, U-Nets).

Strong accuracy on detection (KITTI, Waymo).

Memory and FLOPs grow cubically with resolution.

Quantization loses fine geometry when voxels are coarse.

2. Point-based (PointNet family)

PointNet, PointNet++, PointConv, KPConv

Consume N × 3 points directly. PointNet uses shared MLPs (1×1 convs) plus a permutation-invariant max-pool to get a global feature. PointNet++ adds hierarchical sampling/grouping for local structure.

No quantization; preserves geometry exactly.

Permutation-invariant by construction.

Up to ~80% of runtime is spent on neighborhood lookup / data structuring, not on real feature extraction.

Pure global pooling (vanilla PointNet) misses local context.

3. Graph CNNs

DGCNN, Graph-CNN, PointNGCNN

Build a kNN-graph over the points using XYZ distance, then apply spectral or edge-conv operations to mix neighbor features.

Captures local geometry without a fixed grid.

Naturally rotation-friendly with the right edge features.

Graph construction per layer is expensive at scale.

4. Hybrid Point–Voxel SOTA

PVCNN, MPVConv, PV-RCNN

Keep points for fine detail, but voxelize a coarse copy in parallel for cheap large-receptive-field convolutions; fuse the two branches.

Best speed/accuracy trade-off in current benchmarks.

Avoids both the O(R³) voxel cost and the kNN bottleneck.

More moving parts; harder to implement from scratch.

Why traditional CNNs fail on raw XYZ

  • Unordered: the same scene can be encoded as N! different matrices — the network must be permutation-invariant.
  • Irregular density: nearby points may be very dense or very sparse, so a fixed kernel size has no natural meaning.
  • Sparsity: >95% of any reasonable voxel grid is empty — dense 3D conv wastes most of its compute.
  • Rigid-motion sensitivity: XYZ values change under rotation/translation, so vanilla CNNs are not equivariant.

Practical recipe

  • Small object classification (ModelNet40, ShapeNet): PointNet++ or DGCNN are still strong baselines and easy to train.
  • Outdoor LiDAR detection: sparse 3D-CNNs (MinkowskiNet, SECOND) or pillar/voxel-based detectors dominate.
  • Indoor segmentation (S3DIS, ScanNet): KPConv or sparse-conv U-Nets.
  • If you need both speed and accuracy: reach for a point–voxel hybrid.
