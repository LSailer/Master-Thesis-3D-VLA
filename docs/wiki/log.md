## [2026-04-30] design | Encoder Fusion Plan — pose-aware, geometry-preserving encoder ablation | source: design conversation with Claude
Plan to fix the VGGT encoder confounders #87/#88/#89: current path flattens `world_points (37,37,3)` + `camera_pose (9)` to 4116 floats and projects with a single Dense layer, destroying geometry and drowning pose (0.22% of dims, ~100× smaller magnitude). Four variants share the existing R2Encoder backbone and differ only in pose injection: `vggt_tile` (CoordConv broadcast), `vggt_film` (per-channel γ/β modulation), `vggt_plucker` (per-pixel rays from Habitat extrinsics + intrinsics), `vggt_xattn` (token-level cross-attention with k=8 pose queries on DINOv2 patch tokens). Patch tokens exposed via fixed 1024→64 projection inside the PyTorch extractor (~91k floats/step, 22× current buffer size). Diagnostics: training-time `pose_grad_norm` + eval-time pose-ablation SR drop — the "money diagnostic" for the thesis claim that 3D features only help if pose can influence the latent. Run matrix: 12 H100 runs (4 encoders × 3 seeds), all hyperparameters held to the act_entropy=3e-2 baseline, x-attn deferred as exploratory follow-up. Branch: `feat/encoder-fusion-ablation`. Wrote methods/encoder-fusion-plan.md, updated index.
