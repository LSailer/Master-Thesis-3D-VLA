Episodic VGGT Scene Cache statt per-step 3D-Replay

Die Idee ist sinnvoll, aber nicht als simples "VGGT live nutzen und nichts speichern". In R2Dreamer trainiert der World Model Posterior aus zufaellig gesampelten Replay-Fenstern. Wenn die 3D-Repräsentation nur im aktuellen Stream lebt, sieht Acting eine andere Beobachtung als Training. Der saubere Vorschlag ist deshalb: zuerst einen Streaming-/InfiniteVGGT-Upperbound messen, dann einen replay-kompatiblen, kompakten Episode-Cache-Readout bauen.

Executive Verdict

Der beste Experimentname ist vggt_episode_cache. Das beschreibt exakt den wissenschaftlichen Claim: VGGT soll nicht mehr als isolierter per-step Feature-Generator behandelt werden, sondern als episode-lokale 3D-Szene, die ueber Agentenbewegung hinweg Kontext akkumuliert.

Die erste Implementierung sollte aber nicht den Replay-Buffer komplett von 3D befreien. Sie sollte einen Cache-Upperbound oder einen kompakten Cache-Readout speichern, damit Training, Checkpoints und sampled replay windows reproduzierbar bleiben.

Der eigentliche Claim ist groesser als Storage: Eine ueber die Episode oder das Haus aufgebaute 3D-Repräsentation koennte dem Agenten strukturelle Information geben, die ein einzelner Frame nicht traegt. Der Buffer ist nur die Stelle, an der diese Hypothese mit Dreamer-Replay kompatibel gemacht werden muss.

Why This Is a Scene-Memory Experiment

Die zentrale Frage ist nicht nur, ob wir weniger Bytes im Replay brauchen. Die wissenschaftliche Frage ist, ob eine persistente 3D-Repräsentation des Hauses dem Agenten mehr Kontext gibt: Was wurde schon gesehen, wie haengen Beobachtungen raeumlich zusammen, und kann das World Model dadurch schneller oder stabiler ObjectNav lernen? Der Replay-Buffer ist dabei die technische Schnittstelle, nicht der eigentliche Zweck des Experiments.

Current path What happens today Consequence for the scene-memory proposal
HybridObsAdapter.transform() Runs VGGT every env step, builds [rgb64 | wp_cp], stores the full flat vector. The current design gives every step its own frozen 3D readout; the new hypothesis asks whether a shared house/episode context is more useful.
ReplayBuffer.sample() Samples random contiguous windows and returns numeric batch["obs"]. Training still samples old windows, so each sampled window needs access to the scene context that was available then.
JAXVGGTFeatureExtractor Already keeps streaming KV/cache state and resets at episode boundaries. The repo already has the primitive for accumulating multi-view context; the experiment should test whether that context improves learning.
R2DreamerAgent.train_step() Trains encoder, RSSM, losses, branch gates from replay observations. To make the claim clean, train-time observations must include the same scene-memory signal that acting used live.

External Direction

The web search supports the same design pressure: VGGT-style geometry is moving toward streaming and bounded cache management, not unbounded per-frame token replay.

  • VGGT is the base feed-forward geometry model: camera, depth, point maps, tracks from multiple views.
  • XStreamVGGT targets KV-cache compression for streaming VGGT-like inference.
  • OVGGT frames the key problem as constant-cost streaming 3D reconstruction.
  • StreamCacheVGGT argues for cache scoring and compression rather than pure eviction.

Proposed Implementation Path

1

Upperbound

Run infinite_vggt_stream_upper: keep current replay format, but produce features from the strongest feasible streaming cache context.

2

Replay-Compatible Cache Readout

Store compact deterministic readouts, not the whole cache: WP/CP, pooled aggregator, or 4x4/8x8 pooled token grid.

3

Prefix-Replay Probe

For small L1 windows, reconstruct the cache from the episode prefix before sampling. This is slow but scientifically clean.

4

Production Variant

If upperbound helps, implement vggt_episode_cache_wp_cp or vggt_cache_readout_pooled8 as a new encoder spec.

Concrete Code Changes Later

  1. Add a new adapter beside src/r2dreamer/adapters/hybrid_adapter.py, not by mutating the existing hybrid path.
  2. Add a new encoder variant in src/r2dreamer/encoders/specs.py and registry coverage.
  3. Keep train and val adapters isolated; cache sharing across val/train would invalidate evaluation.
  4. Keep is_first and extractor reset() as hard contracts.
  5. Add tests for buffer shape, adapter reset, sampled-window replay parity, and no cache leakage across episodes.

Main Failure Modes

  • Replay mismatch: sampled windows lack the hidden prefix that created the cache.
  • Future leakage: offline cache construction accidentally uses frames after time t.
  • Reset leakage: cache carries context across episodes or into validation.
  • Cache helps geometry but not ObjectNav semantics.
  • Throughput improves in replay memory but remains blocked by per-step extraction.
  • Large cache becomes an external memory oracle rather than a fair encoder comparison.

Decision Gate

Continue only if the upperbound improves stable SR/SPL under matched seed, step budget, replay capacity, no in-run video/val overhead, and the same fixed evaluation protocol.

If the upperbound does not beat current WP/CP or hybrid controls, a custom persistent scene cache is probably not worth the implementation cost. If it does, the thesis story becomes strong: single-step VGGT readouts underuse multi-view geometry, while an episodic 3D memory recovers the useful signal.
