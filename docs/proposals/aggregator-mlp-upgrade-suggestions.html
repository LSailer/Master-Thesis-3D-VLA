Aggregator MLP — Upgrade Suggestions

Five concrete ways to replace the mean-pool / single-Dense path with r2dreamer-style 3×(Linear + RMSNorm + SiLU) + symlog, ordered cheapest → heaviest.
Branch context: feat/variant-1-aggregator-mlp · 2026-05-16
Source reports: onboarding-mlp-encoder.html · dreamer-vector-input-research.html

Valid as of: commit 34f8c05 · 2026-05-16 · branch feat/variant-1-aggregator-mlp. Heads up: file-path citations in this doc (e.g. networks.py:457) predate PR #145 — the Flax encoder now lives at modules/r2dreamer/world_model/encoders.py:61. Apply the suggestions there.

TL;DR. The current pipeline does mean-pool before the replay buffer plus a single nn.Dense(1024) after it. The r2dreamer MLP pattern (3 Linear layers + RMSNorm + SiLU, with symlog on the input) is what DreamerV3 itself uses on vector observations — so the highest-leverage, lowest-risk change is to apply it to the agent-side encoder (Suggestion #1). Suggestions #3 and #4 alter what gets pooled (richer signals into the buffer); Suggestion #5 trains the pool end-to-end. Anything that changes the adapter before the buffer is bounded by storage — you can't store all 1374 tokens for 5000 frames (≈28 GB).

SUG 1  ·  RECOMMENDED FIRST DROP-IN

Replace the single Dense(1024) with r2dreamer’s 3-layer MLP + symlog

Keeps mean-pool unchanged — only the Flax encoder body changes. This is exactly the MLP r2dreamer uses for proprioceptive vector inputs (3 Linear blocks, RMSNorm, SiLU, optional symlog). See diagram in dreamer-vector-input-research.html §4.

Why this is the right place to start. A single Dense with no norm on un-symlogged VGGT activations very likely produces scale mismatches with the RSSM’s deter+stoch concatenation. So #1 fixes a problem you may not have realized you had — before you start architecting fancier pools.
SUG 2  ·  ABLATION CONTROL

Just add symlog — smallest possible change

Wrap the existing single Dense(1024) input in symlog. Tests the “were the inputs simply miscalibrated?” hypothesis in isolation, separately from the MLP-depth change.

SUG 3  ·  RICHER POOL, CHEAP STORAGE

Multi-statistic pool: mean + max + std → r2dreamer MLP

Mean alone throws away most of the token distribution. Compute mean, max, std across the 1374 tokens at adapter time, concatenate to (3072,), then run the 3-layer MLP+symlog on the agent side. Buffer grows only 3×.

SUG 4  ·  SEMANTICALLY-AWARE POOL

Special-token bypass: drop patch noise, keep the 5 special tokens

Of the 1374 tokens, only the first 5 are special (1 camera + 4 register). VGGT’s global-attention blocks are trained to write summary scene state into these. Mean-pooling all 1374 dilutes them 274× with patch noise.

  • vggt_adapter.py — tokens[:5], flatten to (5120,); optionally add a single mean-pool of the patch tokens too → (6144,)
  • networks.py — 3-layer MLP+symlog with input 5120 or 6144

1 # vggt_adapter.py

Caveat. The semantic meaning of the 4 register tokens depends on the VGGT checkpoint — some are dominated by camera-pose-related signals; others encode global geometry. Worth probing them once with a quick PCA / cosine-sim viz before betting heavily on this variant.
SUG 5  ·  AMBITIOUS / RESERVE

Learned attention-pool: train the aggregator end-to-end with the world model

Sub-sample the 1374 tokens to a small fixed set (e.g. ~37: 5 special + 32 strided patch tokens), store those in the buffer, then on the agent side run a learned attention-pool (single query, multi-head attention) → (1024,) → 3-layer MLP+symlog. The pool itself is now trained jointly with the RSSM and value/reward heads.

Don’t start here. If you jump directly to attention-pool, any improvement is confounded with the missing MLP capacity (Sug 1) and the missing input compression (Sug 2). Run those first; otherwise you cannot tell what is actually contributing the gain.

Recommended ordering & ablation matrix

Each row is independently testable against your size12M smoke-run baseline. vggt_aggregator_mlp stays as the encoder-spec name across all of them — only the Flax module body and (for Sug 3–5) the adapter transform() change.

OrderVariantWhat you isolateIf gain > 0 vs baseline, conclude…
1 Sug 2 — symlog only Input scale VGGT activations were miscalibrated for an unnormalised Dense.
2 Sug 1 — full r2dreamer MLP+symlog + Non-linear capacity The encoder needs more than one linear projection to feed the RSSM well.
3 Sug 3 — multi-stat pool + MLP + Richer pooled signals Mean alone was discarding distributional information VGGT tokens carry.
4 Sug 4 — special-token pool + MLP + Semantic-aware pooling Patch tokens were noise; VGGT’s 5 special tokens carry the useful summary.
5 Sug 5 — learned attention-pool + End-to-end training of the pool Static pooling is a real ceiling — world-model gradients should reshape it.

Register the change as a config flag (encoder.mlp.layers, encoder.mlp.symlog_inputs, encoder.pool: mean | multistat | special | attention) instead of hard-coding, so each prior step remains a one-line-diff ablation.
