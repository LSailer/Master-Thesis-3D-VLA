Architecture Memo · 2026-05-16

Five domain-driven refactors for src/

The top-level split into r2dreamer / vggt / envs / shared / baselines is sound — there are no cyclic dependencies and the dependency direction (r2dreamer → vggt, envs) is correct. The pain lives inside modules: god-files, leaky shared kernel, concrete cross-module coupling, monolithic configs, and a duplicated perception backend with no unifying port.

Status as of 2026-05-17: Suggestion 2 is already shipped in PR #145 (commit 613b5c6) — world_model/, behavior/, representation/ subpackages now exist. Suggestions 1, 3, 4, 5 remain open; Suggestion 5 is partially done (subpackages exist, per-subdomain configs do not yet). Originally generated 2026-05-16 at commit 34f8c05.

In this memo
  1. Demote src/shared/ to a true generic kernel
  2. Carve r2dreamer/ into bounded subdomains
  3. Define explicit ports at every seam
  4. Split Trainer into an application layer
  5. Decompose R2DreamerConfig by subdomain
Suggestion 1 Effort · Low

Demote src/shared/ to a true generic kernel

A shared kernel must not know about its callers. Today, shared/ branches on Dreamer types.
Symptom src/buffer/replay_buffer.py:33–39 accepts either a BufferConfig or a DreamerConfig/R2DreamerConfig and reaches into buffer_capacity / obs_shape fields. shared/configs.py defines only DreamerConfig with ObjectNav-specific knobs (num_actions=4, reward_type="geodesic_delta", success_bonus). This isn’t a shared kernel — it’s a hidden third bounded context that pretends to be infrastructure.

Proposed split

Before
src/shared/
  replay_buffer.py   # knows DreamerConfig
  configs.py         # only DreamerConfig
  optim.py           # truly generic
  wandb_utils.py     # truly generic
After
src/kernel/                # truly generic
  optim.py                     # laprop, agc
  logging/wandb_utils.py       # init_run, EpisodeTracker
  replay/                      # schema-agnostic ring buffer
    buffer.py                  # BufferConfig only
    val_dataset.py

src/r2dreamer/
  replay/schema.py             # Dreamer obs/action/reward/cont
  replay/adapter.py            # DreamerConfig → BufferConfig
  config.py                    # owns DreamerConfig now

Rule of thumb

A file in kernel/ must compile and pass its tests with zero grep-hits for r2dreamer, Dreamer, ObjectNav, or any other domain word. Treat that grep as a CI gate.

Payoff The kernel becomes reusable for a non-Dreamer baseline (e.g. a PPO ablation) without import gymnastics, and a new reader can answer “is this generic or domain-specific?” from the directory name alone.
Suggestion 2 Effort · Medium

Carve r2dreamer/ into bounded subdomains

One 30 KB agent.py with an 8-term _loss_fn is the textbook anchor module.
Symptom src/r2dreamer/agent.py (30 KB) holds a single _loss_fn() ≈ 200 LOC that simultaneously computes world-model KL, Barlow-Twins representation loss, reward & continue heads, imagination rollout, actor-critic gradients, and replay-based value learning. Every derivative flows through one jax.grad(), so isolating “just the world model” for an ablation forces a fork of the whole loss.

Three sub-bounded contexts inside r2dreamer/

  • WorldModel — RSSM, encoder, decoder, reward & continue heads, KL + recon losses
  • Behavior — actor, critic, imagination rollout, λ-return, ReturnEMA
  • Representation — Barlow-Twins projector + repvalue head (the “R2” in R2Dreamer)
Before
src/r2dreamer/
  agent.py        # 30 KB, all losses
  networks.py     # 19 KB, every nn.Module
  trainer.py      # 21 KB
  config.py       # one big dataclass
After
src/r2dreamer/
  world_model/
    rssm.py          # R2RSSM, Deter, BlockLinear
    encoders.py      # R2Encoder, VGGTEncoder, ...
    heads.py         # reward, continue, decoder
    loss.py          # kl + recon + head losses
    config.py
  behavior/
    actor.py
    critic.py
    imagination.py   # _imagine, _lambda_return
    return_ema.py
    loss.py
    config.py
  representation/
    barlow.py        # Projector + BT loss
    repvalue.py
    loss.py
  agent.py           # ~150 LOC: composes the 3 losses

What stays in agent.py

A thin composition root: read state, call world_model.loss(...), behavior.loss(...), representation.loss(...), sum with scalars from LossWeights, return. The single jax.grad still works — the three losses are pure JAX functions that share inputs but live in different files.

Payoff Ablations become diff-able: turning off the representation loss is a one-line change at the composition root, not a fork of _loss_fn. Each subdomain has its own tests, its own config, its own Wiki page. Reviewing a behavior change no longer requires reading world-model code.
Suggestion 3 Effort · Medium

Define explicit ports at every cross-module seam

Today r2dreamer imports concrete VGGT classes. Tomorrow, replacing the perception backend should be a one-file swap.
Symptom src/r2dreamer/adapters/vggt_adapter.py:11 imports the concrete JAXVGGTFeatureExtractor. src/vggt/feature_extractor.py (PyTorch) and src/vggt/jax/feature_extractor.py (JAX) are two divergent codebases with no shared interface — the only thing that “unites” them is a benchmark script in jax/benchmark_streaming.py:52. Result: r2dreamer is permanently wedded to the JAX path; the PyTorch path is research-only and rotting.

Introduce a ports/ layer

src/r2dreamer/ports/
  perception.py        # PerceptionPort Protocol: features = port(frames)
  env.py               # EnvPort: reset/step typed contract
  replay.py            # ReplayPort: write/sample
  checkpoint.py        # CheckpointPort: save/load(state) -> bytes

Adapters that implement the ports

src/vggt/adapters/
  jax_perception_port.py    # JAXVGGTFeatureExtractor → PerceptionPort
  torch_perception_port.py  # vggt/feature_extractor.py → PerceptionPort

src/environments/adapters/
  habitat_port.py           # HabitatObjectNavEnv → EnvPort
  crafter_port.py           # CrafterEnv → EnvPort

The Pythonic version: typing.Protocol, not ABCs

from typing import Protocol, runtime_checkable
import jax.numpy as jnp

@runtime_checkable
class PerceptionPort(Protocol):
    feature_dim: int
    def __call__(self, frames: jnp.ndarray) -> jnp.ndarray: ...
    def reset(self) -> None: ...
  • Concrete imports to remove: r2dreamer/adapters/vggt_adapter.py:11, r2dreamer/launch/encoders.py:15, r2dreamer/scripts/profile_training.py:14
  • Once PerceptionPort exists, the PyTorch backend stops being dead code — it’s a substitutable implementation behind the same contract.
Payoff Swapping VGGT for a CLIP or DINOv2 encoder becomes a new file in vggt/adapters/ (or perception/dinov2_port.py) — r2dreamer code does not change. Mocking perception in tests becomes a five-line fake instead of a JAX-tracer dance. The PyTorch vs JAX duality stops being a fork and becomes two backends behind one contract.
Suggestion 4 Effort · Medium

Split Trainer into a thin application layer

The Trainer class is the “application service” in DDD terms. Right now it’s also the persistence layer, the metrics layer, and the environment driver.
Symptom src/r2dreamer/trainer.py (21 KB) couples: env stepping, replay buffer management, WandB logging, CSV metric writing, checkpoint pickling, validation rollouts, prefill, and the train-loop schedule. _train_loop and _prefill both stuff env-step logic next to data-flow logic next to logging side effects. Changing the checkpoint format means editing the same file that owns the env step.

Layered split

src/r2dreamer/application/
  trainer.py              # ~120 LOC orchestrator. Knows nothing about wandb/pickle/csv.
  actor_loop.py           # env_step + replay.write (uses EnvPort, ReplayPort)
  learner_loop.py         # sample → agent.update → metrics
  prefill.py
  validation.py

src/r2dreamer/infrastructure/
  checkpoint_pickle.py    # CheckpointPort impl
  metrics_wandb.py        # MetricsSink impl
  metrics_csv.py          # MetricsSink impl
  manifest.py             # already clean — move it here

What composition looks like

trainer = Trainer(
    agent       = agent,
    actor       = ActorLoop(env_port, replay_port, perception_port),
    learner     = LearnerLoop(agent, replay_port),
    checkpoint  = PickleCheckpoint(path),
    metrics     = TeeMetricsSink([WandbSink(...), CsvSink(...)]),
)
trainer.run(steps=N)
  • The actor/learner split mirrors how distributed RL frameworks already partition the work and lays the groundwork for a future async setup without rewriting Trainer.
  • convert_batch() (currently a free function in trainer.py) belongs next to the replay schema, not next to the training loop.
Payoff A new logging sink (e.g. TensorBoard, or your docs/wiki auto-publisher) is a 30-line class implementing MetricsSink. The overfit-one-batch diagnostic (see commit 34f8c05) becomes a different Trainer composition, not a flag inside the trainer that has to be threaded through every method.
Suggestion 5 Effort · Low

Decompose R2DreamerConfig by bounded context

A 50-field dataclass is a UI for a tool, not a domain model.
Symptom R2DreamerConfig in src/r2dreamer/config.py mixes RSSM dims, encoder choice, MLP widths, optimizer hyperparams, loss scale weights, and behavior-policy knobs in one flat dataclass. Adding a new behavior hyperparameter requires touching the same file that owns the encoder choice. Readers have to memorize prefixes (rssm_*, actor_*, repval_*) instead of relying on namespaces.

Composition over flatness

@dataclass(frozen=True)
class R2DreamerConfig:
    world_model:    WorldModelConfig
    behavior:       BehaviorConfig
    representation: RepresentationConfig
    optim:          OptimConfig
    loss_weights:   LossWeights      # one float per subdomain
    obs:            ObsConfig        # shape, num_actions, encoder kind

    @classmethod
    def size25M(cls) -> "R2DreamerConfig": ...

Mapping each subconfig to its owner

  • WorldModelConfig lives in r2dreamer/world_model/config.py
  • BehaviorConfig in r2dreamer/behavior/config.py
  • RepresentationConfig in r2dreamer/representation/config.py
  • OptimConfig in kernel/optim.py (truly generic)
  • LossWeights at the composition root — it’s the one place that knows about all three subdomains

This composes naturally with Suggestion 2: each new subpackage owns its own config dataclass and its own defaults. The top-level R2DreamerConfig becomes a 6-line struct that documents the bounded contexts by its field names alone.

Payoff CLI parsers (src/r2dreamer/launch/parser.py) can mirror the structure with --world-model.deter-size 512-style grouping. Sweep configs in scripts/slurm become readable: a sweep over behavior LR doesn’t touch the world-model config block.

Suggested order of attack

  1. Suggestion 5 first — pure dataclass refactor, no behavior change, easy to revert.
  2. Suggestion 1 next — mostly file moves + a rename of shared/ to kernel/. CI grep gate locks the result in.
  3. Suggestion 3 in parallel — ports are additive, no callers break until you delete the concrete imports in a final pass.
  4. Suggestion 2 after ports exist — carving agent.py is safer once the world-model is a named seam.
  5. Suggestion 4 last — Trainer is downstream of all of the above and benefits the most from them already being in place.
