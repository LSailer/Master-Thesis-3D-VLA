2.1   Temporal drift after PR #145

The current main already includes 613b5c6 — “split agent into world_model/behavior/representation packages.” That refactor moved code after these docs were generated:

What the docs cite

  • modules/r2dreamer/networks.py:457–478 — Flax VGGTAggregatorMLPEncoder
  • modules/r2dreamer/networks.py:108–109 — MLP routing for 2-D specs
  • modules/r2dreamer/agent.py:425 — stop_gradient on encoder embedding inside Barlow loss
  • 30 KB agent.py, 19 KB networks.py

What main now has

  • modules/r2dreamer/world_model/encoders.py:61 — Flax VGGTAggregatorMLPEncoder
  • networks.py is now 875 bytes (effectively gutted)
  • stop_gradient calls live in behavior/loss.py (lines 42, 45, 56, 57, 63, 67, 71, 106) and behavior/imagination.py (36, 37)
  • agent.py is 17.8 KB; trainer.py 21 KB (still matches)

2.4   Re-verify the overfit-one-batch smoking gun

overfit_one_batch_aggregator_mlp.html opens with a strong claim: “agent.py:425 applies jax.lax.stop_gradient to the encoder embedding inside the Barlow loss.” But after PR #145, the Barlow loss now lives in modules/r2dreamer/representation/, and the stop_gradient calls I located are in behavior/loss.py (around the imagined-rollout boundary, which is normal and expected) and behavior/imagination.py. None of those obviously sit inside the representation/Barlow path on the encoder embedding.

Before publishing this diagnostic, re-grep for stop_gradient inside representation/barlow.py and representation/loss.py and update the citation. If the smoking gun no longer exists, the doc's framing (“the encoder receives no Barlow signal”) needs to be rewritten or downgraded to “hypothesis we ruled out, here's what we found instead.” This is the only doc whose conclusion, not just its citations, could be invalidated by the refactor.
