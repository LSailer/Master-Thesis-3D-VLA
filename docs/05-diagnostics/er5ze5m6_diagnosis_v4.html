  1. low Actor-loss weight is missing the /disc correction. r2dreamer trains the continue head on raw 1−is_terminal (matches official contdisc=False) and applies γ externally — but skips the /disc divisor that Hafner uses to make the first imagined step weighted 1.   2. low Replay-buffer is_first is correct. is_first[:,0]=True; is_first[:,1:]=dones[:,:-1] is post-reset semantics — confirmed via synthetic trace and against danijar/dreamerv3's _annotate_batch. No bug.
  3. caveat Critic/reward head bin geometry — the user's concern needs a refinement. But — and this is important — danijar/dreamerv3@main's current symexp_twohot head also uses identity squash by default. Both use the same symexp(linspace(−20, 0, 127))-mirrored bins. If the comparison target is the modern reference, the heads are gradient-equivalent. If the target is the older Hafner 2023 paper or the R2-Dreamer PyTorch reference (which may apply symlog to targets), the divergence is real. 1 — Actor-loss block: continue-head target + per-step weight

1.1 — The contdisc design

In danijar/dreamerv3, the contdisc flag (default True in configs.yaml:82) decides whether the discount γ is baked into the continue-head target or applied externally in the actor loss.

Crafter-original (danijar/dreamerv3@main)

# agent.py:158–160 — continue-head target
con = f32(~obs['is_terminal'])
if self.config.contdisc:
    con *= 1 - 1 / self.config.horizon

# agent.py:280–281 — actor weight
disc = 1 if contdisc else 1 - 1/horizon
weight = jnp.cumprod(disc * con, 1) / disc

With contdisc=True (default): head learns γ·1{not_terminal}; weight = cumprod(con,1). With contdisc=False: head learns raw 1{not_terminal}; weight = cumprod(disc·con,1) / disc — the /disc makes step 0 weight = 1.

r2dreamer (this thesis)

# agent.py:442–449 — continue-head target
cont_target = 1.0 - batch["is_terminal"]
losses["con"] = jnp.mean(
  optax.sigmoid_binary_cross_entropy(
    cont_logits[..., 0], cont_target))

# agent.py:500–502 — actor weight
disc = 1.0 - 1.0 / cfg.horizon
# Match original: weight = cumprod(cont * disc) over all horizon steps
weight = jnp.cumprod(imag_cont * disc, axis=1)

Trains on raw binary (matches contdisc=False) but the /disc divisor is missing.

1.2 — Effect on the per-step weight

weightreft  =  γt−1 · ∏s≤t ĉs   vs   weightr2t  =  γt · ∏s≤t ĉs
i.e. r2dreamer's weight is uniformly γ × the reference. With γ = 1 − 1/333 ≈ 0.99700, a constant ~0.3% shrink per imagined step relative to the published implementation.
Verdict: not a bug, doesn't change relative gradients. Worth a one-line fix (weight = jnp.cumprod(imag_cont * disc, axis=1) / disc) so published learning rates from danijar/dreamerv3 are directly transferable. Same conclusion as v3 §3, now with explicit citation of the contdisc dispatch in the reference.

2 — Replay buffer: is_first verification

The hypothesis was that the post-reset/pre-reset semantics might be off-by-one. They are not.

// modules/shared/replay_buffer.py:85–87
is_first = np.zeros_like(dones)
is_first[:, 0] = True
is_first[:, 1:] = dones[:, :-1]

Synthetic trace — dones = [0, 1, 0, 0]

The official danijar/dreamerv3 uses the same convention via embodied/core/replay.py's _annotate_batch: it forces the first column to True and inherits the per-step is_first field from upstream env-wrapper code (which tags the post-reset observation). Same semantics.

Verdict: verified correct. No off-by-one. The replay sampler can produce windows that span two episodes, and the RSSM resets mid-window correctly. This finding closes one of the v1/v2 hypotheses (the "is_first stuck at 1" failure mode is not happening here).

3 — Critic / reward head: bin geometry — important nuance

This is the most consequential of the three findings, but it requires resolving an ambiguity in the comparison target.

3.1 — What R2TwoHotDist actually does

// modules/r2dreamer/networks.py:11–28
def _symexp(x):
    return jnp.sign(x) * jnp.expm1(jnp.abs(x))

def _make_bins(num_bins: int = 255):
    """Build R2-Dreamer's symexp-spaced bins in real space.
    Matches PyTorch: symexp(linspace(-20, 0, half)) mirrored.
    """
    if num_bins % 2 == 1:
        half = jnp.linspace(-20.0, 0.0, (num_bins - 1) // 2 + 1)
        half = _symexp(half)
        bins = jnp.concatenate([half, -half[:-1][::-1]])
    ...
    return bins

// modules/r2dreamer/networks.py:31–41
class R2TwoHotDist:
    """TwoHot distribution matching R2-Dreamer's real-space parameterization.
    Unlike DreamerV3's TwoHotDist (which operates in symlog space), this uses
    bins = symexp(linspace(-20, 0, 128)) mirrored to 255 bins in real space.
    No symlog/symexp transform is applied to targets or predictions.
    """
    def __init__(self, num_bins: int = 255):
        self.num_bins = num_bins
        self.bins = _make_bins(num_bins)

So the bins are not uniform in real space — they are symexp-spaced, which means densely packed near 0 and exponentially sparse out to ±exp(20)−1 ≈ ±4.85·10⁸. The "no symlog/symexp transform" comment refers to the absence of a target squash, not to the bin spacing itself.

3.2 — What danijar/dreamerv3@main currently does

// embodied/jax/heads.py:132–144 — symexp_twohot
def symexp_twohot(self, x):
    assert not self.space.discrete
    shape = (*self.space.shape, self.bins)
    logits = self.sub('logits', nets.Linear, shape, **self.kw)(x)
    if self.bins % 2 == 1:
        half = jnp.linspace(-20, 0, (self.bins - 1) // 2 + 1, dtype=f32)
        half = nets.symexp(half)
        bins = jnp.concatenate([half, -half[:-1][::-1]], 0)
    else:
        half = jnp.linspace(-20, 0, self.bins // 2, dtype=f32)
        half = nets.symexp(half)
        bins = jnp.concatenate([half, -half[::-1]], 0)
    return outs.TwoHot(logits, bins)

Note squash defaults to identity. The symexp_twohot factory does not pass a squash kwarg — it only uses symexp for the bin spacing. So the modern reference and the fork are doing the same thing on the gradient path: symexp-spaced bins, identity squash on targets.
