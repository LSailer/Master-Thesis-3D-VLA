Restructuring toward modules, components, and tested interfaces

An overview of established patterns — from O'Reilly books, canonical blogs, and reference ML repos — and how each maps onto the current Master-Thesis-3D-VLA codebase. The aim: a structure where the interfaces are the tested contract, and the implementations behind them are free to churn.

Branch surveyed: feat/variant-1-aggregator-mlp · Generated 2026-05-11

Scope of this restructuring. The top-level split under modules/ is already healthy: envs/, vggt/, shared/, and baselines/ are each independent modules with their own tests. The work below targets inside modules/r2dreamer/ only — the 6.9 KLOC training package where agent.py, networks.py, and trainer.py have grown into mixed-concern monoliths.

2 · Seven patterns from the canon

Each card: what it is, how testing works under it, and fit for thesis-scale ML code. Sources are cited inline; full URLs in §8.

① Ports & Adapters (Hexagonal)

Cockburn 2005 Hombergs, O'Reilly

The application core owns the ports (interfaces it needs); external tech plugs in as adapters. Cockburn's goal: "Allow an application to equally be driven by users, programs, automated test or batch scripts, and to be developed and tested in isolation from its eventual run-time devices and databases."

Testing. Drive the core through inbound ports while substituting fakes for outbound ports (e.g., in-memory replay buffer for the real one). Adapters get their own integration tests.

Fit. Strong for stable seams (encoder, env, logger). Overkill if you port-ify every helper.

② Clean Architecture (Dependency Rule)

Martin 2012/2017

Concentric layers; source dependencies point only inward. Plain data crosses boundaries.

Testing. Entities + use cases run with no framework. Frameworks themselves are trusted, not tested by you.

Fit. Take the Dependency Rule ("training code never imports wandb or hydra directly") and drop the four-layer ritual — "entity vs use case" is awkward for a world model.

③ Dependency Inversion + typing.Protocol

Percival & Gregory, O'Reilly Ramalho, O'Reilly

High-level code depends on a Protocol, not a concrete class. In Python this is duck typing made explicit and type-checkable — no inheritance required.

Testing. Any double satisfying the protocol works — even a trivial dataclass returning fixed tensors.

Fit. Excellent. Zero runtime overhead, integrates with mypy/pyright. Your Env(Protocol) already follows this — extend it to EncoderProtocol, BufferProtocol, LoggerProtocol.

④ Strategy + Registry

GoF 1994 Cockburn

A family of interchangeable algorithms behind one interface. A registry maps name → factory. Already in your repo as encoder_registry.

Testing. Test each strategy against the shared contract (input → valid-shape output). Test the registry resolves. Don't compare implementations' numbers — that's not the contract.

Fit. Made for ablations. Pair with Hydra's _target_ (⑦). Weakness: registries hide imports from static analysis — keep them small and centralized.

⑤ Test the interface, not the implementation

Feathers 2004 Beck (Chicago/London)

Pin the observable contract — inputs, outputs, declared collaborators. Chicago-style: assert final state with real collaborators. London-style: mock collaborators and assert calls.

Testing. Public methods on the seam. Not: private helpers, intermediate tensor shapes, caching.

Fit. This is the principle you want. Lean Chicago — mock-heavy tests over numerical code lock in incidental call patterns and become churn liability.

⑥ Deep Modules, Narrow Interfaces

Ousterhout 2018

A deep module hides substantial logic behind a small interface. A shallow module's interface is almost as wide as its body — pure tax.

Testing. Narrow interface = few entry points, each exercising a lot of code. Tests double as the spec.

Fit. The most actionable principle. Aim for ~5–7 deep modules: Encoder, WorldModel, Actor, EnvAdapter, Trainer, Evaluator, RunLogger. Don't add TrainerStateManager + EpochScheduler + MetricFlusher shallow trios.

⑦ Configuration as Composition (Hydra / OmegaConf)

FAIR / Hydra docs PyTorch blog

YAML (not Python wiring) chooses which concrete class fills each port. hydra.utils.instantiate({"_target_": "encoders.VGGT", "freeze": True}) is constructor injection driven by config. Groups compose: model/vggt.yaml + env/hm3d.yaml + train/dreamer.yaml.

Testing. Instantiate components from minimal Python dicts, not YAML. The Hydra layer itself is trusted. Test each registered _target_ satisfies its Protocol.

Fit. Near-canonical for ML. Pairs naturally with ③ + ④. Caveat: Hydra changes cwd, captures sys.argv, and resists pytest — keep an instantiate_from_dict(cfg) seam so unit tests bypass Hydra.

3 · ML-specific patterns & reference repos

Lightning-style boundaries

PyTorch Lightning splits code into four orthogonal layers: research code (LightningModule), engineering code (Trainer), callbacks, and data (LightningDataModule). The LightningModule exposes a fixed ~20-method contract — those methods are the interface. For a Dreamer-style agent the analogue is one WorldModelAgent class with observe / imagine / act / update, leaving the orchestrating Trainer entirely separate.

Registry pattern in the wild

Detectron2 ships BACKBONE_REGISTRY, META_ARCH_REGISTRY — "each registry provides the ability to replace components with customized versions, without having to modify the framework's code." MMDetection inherits its registry from MMEngine. Stable-Baselines3 keeps a small policy registry per algorithm.

For a single-author thesis, Hydra's _target_ (fully-qualified Python path) usually beats a homegrown registry — same plug-in effect, no global state, IDE jump-to-definition still works. Your current encoder_registry is small enough to keep, but don't grow more of them.

Research vs production — guardrails against over-engineering

  • Karpathy, A Recipe for Training Neural Networks: "Don't be a hero… copy-paste a ResNet-50 for your first run." Nets "fail silently"; abstractions can hide bugs. Introduce an abstraction the second time you copy-paste, not the first.
  • Patrick Kidger, Just know stuff: academic code is "a poorly-maintained kludge of leaky abstractions." Avoid both "spaghetti and ravioli code" — too-flat and over-abstracted both lose.
  • Chip Huyen, Designing Machine Learning Systems (O'Reilly 2022): ML systems are "part code, part data, part artifacts" — modularity must include data & configs, not just classes.
  • Joel Grus, I Don't Like Notebooks (JupyterCon 2018): notebook kernel state breaks reproducibility. Keep training entry points as .py files runnable end-to-end; reserve notebooks for plotting.

4 · Which patterns pair well

CombinationWhy it works for thesis code
Protocols ③ + Strategy/Registry ④ + Hydra ⑦ The mainstream ML-research stack. Protocol pins the contract; registry/Hydra _target_ enumerates implementations; YAML selects one. Highest leverage for encoder/aggregator ablations.
Ports & Adapters ① + Protocols ③ Ports become Python Protocols, adapters are concrete classes. No ABC boilerplate; mypy enforces the contract.
Deep Modules ⑥ + Test-the-interface ⑤ Narrow interface → small test surface → stable tests across reimplementations. This is the pairing you asked for, philosophically.
Clean Architecture ② — Dependency Rule only Keep as a one-line invariant ("the trainer never imports wandb"), drop the layer scheme.
Avoid: London-mockist TDD (⑤) over numerical pipelines Mocks pin call patterns; numerical code mutates call patterns constantly. Stay Chicago-style: assert shape, dtype, finiteness, loss-decreases — not "encoder.encode was called twice."

5 · Concrete recipe for this thesis

Minimal stack: Protocols define seams (Encoder, Aggregator, Env, Logger, Buffer) → Hydra _target_ injects implementations → Chicago-style tests assert the contract per Protocol → one deep Trainer module orchestrates. Skip the full hexagonal / Clean Architecture ceremony; keep only the Dependency Rule.

Target layout (incremental — you don't need to migrate everything in one pass). The other top-level modules stay untouched:

6 · Migration map — what to extract, in order

StepFromToWhy
1 trainer.py L31–34 (Env Protocol) interfaces/env.py Already a Protocol; just relocate so it's discoverable.
2 launch/encoders.py (Encoder ABC) interfaces/encoder.py as Protocol Replace ABC with typing.Protocol — drops inheritance constraint, gains structural typing.
3 networks.py L8–64 (TwoHotDist, distribution helpers) losses.py Networks file should be modules only. Loss math is a separate concern.
4 networks.py L457–474 (VGGTAggregatorMLPEncoder) + siblings encoders/{cnn,vggt,vggt_aggregator_mlp}.py One file per encoder. All satisfy EncoderProtocol; register via _target_.
5 agent.py RSSM + heads world_model/ Shrink the 773-LOC monolith. Agent becomes a composition of encoder + world model + actor/critic.
6 trainer.py convert_batch L41–56, checkpoint L63–87 trainer/{batch.py, checkpoint.py} Each becomes a small unit with its own contract test (round-trip).
7 Three parallel config dataclasses Hydra groups + structured configs encoder=vggt_aggregator_mlp env=hm3d agent=r2dreamer on the CLI. Stop hand-wiring.

Karpathy's rule applies. Don't do steps 1–8 in one PR. Each step should leave the repo green and a number reproducible. Pin a code/ SHA in the writing repo before each restructure step so a reviewer can diff results.

6.5 · One-shot vs milestones

Milestones — strongly. A single big-bang refactor fails on three concrete grounds in this repo:

  1. Tests are too sparse to verify equivalence. No trainer-loop test, no checkpoint round-trip. Without a safety net, "the refactor compiles" ≠ "the refactor reproduces yesterday's loss curve."
  2. Flax param-tree paths are positional. Moving a flax.linen.Module to a new file or class often changes the param-tree path → old checkpoints fail to load silently or with garbage values. You want this in bounded PRs, not scattered.
  3. feat/variant-1-aggregator-mlp is active. A big-bang rewrite freezes the ablation; milestones let you keep training between them.

Suggested milestone breakdown

# Milestone What moves Checkpoint impact Risk
M0 Safety net (no code moves) Add: 1-step overfit tests for CNN + VGGT encoders, checkpoint round-trip test, baseline loss curve pinned by SHA. none low
M1 Pure relocations, no semantics Env(Protocol) → envs/; Encoder ABC → shared/interfaces/ as Protocol; extract losses.py from networks.py. Import shuffling only — no class renames. none low
M2 The two §7 leaks Split shared.DreamerConfig → BufferConfig/RunConfig + r2dreamer-local hyperparams. Move Flax VGGT modules from networks.py to vggt/jax/heads/. invalidates VGGT checkpoints medium
M3 Shrink the monoliths Extract world_model/ and actor_critic/ from agent.py. Split trainer.py into loop.py + checkpoint.py + batch.py. invalidates all checkpoints medium-high
M4 Config-as-composition (defer until ablations are closing) Hydra adoption + structured configs. none low
Bundling rule for checkpoint invalidation. M2 and M3 both change the param tree. If you can afford one retrain cycle, do them back-to-back so you only invalidate once.
Gate between milestones. Each PR must pass M0's contract tests and reproduce the pinned baseline number (record the code/ SHA in writing/). If a milestone breaks a number, bisect before opening the next.
Why M4 is last. Hydra is high-value but pure plumbing. Doing it after the ablations rather than during them removes one moving variable from the variant-1 results.

7 · Dependency boundaries — what r2dreamer/ owns

The test for "does this belong in r2dreamer/?" is one question: does the code need to know that R2Dreamer / RSSM / Dreamer losses exist? If no, it lives elsewhere. The dependency rule (arrows one direction only):

launch ──▶ r2dreamer ──▶ shared ──▶ stdlib, jax
              │
              ├──▶ envs    (only through the Env protocol)
              └──▶ vggt    (only through FeatureExtractor)

Nothing in envs/, vggt/, or shared/ ever imports from r2dreamer/. If it does, that's a smell to fix before any restructuring.

What r2dreamer/ must own

Code that touches RSSM state, Dreamer losses, or the agent's parameter pytree:

SubmoduleWhy it must live here
world_model/ — RSSM + dynamics + reward/cont/decoder headsOwns the latent-state type. Pure Dreamer.
actor_critic/ — policy + valueReads world-model latents. Dreamer-specific.
agent.py — slim composerOwns AgentState (params + opt state); exposes act / train_step.
losses.py — TwoHotDist, KL balancing, Barlow TwinsDreamer-specific math (currently buried in networks.py L8–64).

├── actor_critic/        # policy + value
├── encoders/            # CNN only (VGGT lives in vggt/)

Every import inside this tree resolves to r2dreamer.*, shared.*, envs.*, or vggt.* — never the reverse. Enforce this mechanically with one rule in CI:

grep -r "from r2dreamer" modules/envs/ modules/vggt/ modules/shared/ \
  && echo "Dependency rule violated" && exit 1
Two leaks to fix first — they unlock everything else:
  1. shared/configs.py:DreamerConfig — rename & split. Once shared/ no longer mentions Dreamer, the directed-graph rule above is real.
  2. Flax VGGTEncoder modules in networks.py — move into vggt/. Then vggt/ is the single home of "anything VGGT."

8 · Interface-only testing — what to actually assert

"Test the interface" is concrete in tensor code. For each Protocol, a contract test asserts:

InterfaceContract test asserts
EncoderProtocol encoder(x).shape == (B, D) for declared x.shape · .dtype == float32 · .device == x.device · no NaN on x = zeros / random · gradients flow (one loss.backward() sets all param.grad).
ReplayBufferProtocol Push/sample round-trip preserves dtype & shape · capacity honored · float16 in / float32 out for VGGT path.
EnvProtocol reset() returns obs matching declared spec · step(action) returns 4-tuple with right dtypes · close() is idempotent.
WorldModelProtocol observe(seq) returns posterior of right shape · imagine(state, T) produces a length-T rollout · KL non-negative on identical posteriors.
TrainerProtocol One update() on a 2-sample fixture decreases total loss · checkpoint save→load is a fixed-point.

Notably not tested: that VGGT and CNN produce similar features, that aggregator-MLP is "better," that intermediate tensor shapes inside an encoder are anything in particular. Those are research questions, measured by runs, not pinned by unit tests.

This is the robomimic recipe codified — output_shape(input_shape) + a forward-pass check is enough to make whole networks composable without running them.
