Barlow Twins Loss in R2-Dreamer

Diese Seite erklärt die konkrete Implementierung in deinem Projekt: nicht als Bild-Rekonstruktion, sondern als Redundanzreduktion zwischen RSSM-Feature feat und Encoder-Embedding embed.

barlow_lambda = 5e-4 scale_barlow = 0.05 Normierung ueber B*T torch.std-Paritaet: ddof=1
cross-correlation C diag -> 1, offdiag -> 0
C = norm(projector(feat))^T norm(embed) / (B*T)
L = sum_i (C_ii - 1)^2 + lambda * sum_{i!=j} C_ij^2

Was die Loss erzwingt

Barlow Twins baut eine Kreuzkorrelationsmatrix Jede Zelle misst, wie stark eine Dimension der projizierten RSSM-Features mit einer Dimension des Encoder-Embeddings zusammenhaengt. zwischen zwei Darstellungen derselben Zeitschritte. In deinem Code sind die Zwillinge nicht zwei augmentierte Bilder, sondern projector(feat) und embed.

\[ C_{ij} = \frac{1}{B T} \sum_{b=1}^{B}\sum_{t=1}^{T} z^{(1)}_{bt,i}\,z^{(2)}_{bt,j} \] \[ \mathcal{L}_{BT} = \sum_i (C_{ii} - 1)^2 + \lambda \sum_{i \ne j} C_{ij}^2 \]

Diagonale Werte stehen fuer Invarianz: passende Dimensionen sollen sich gleichen. Off-Diagonal-Werte stehen fuer Redundanz: verschiedene Dimensionen sollen nicht dieselbe Information tragen.

1

Gleiche Zeitschritte aus Replay

feat und embed kommen aus demselben Batch mit Form (B, T, *).

2

Projektion auf Encoder-Dimension

Der lineare Projector mappt RSSM-Features von feat_size auf embed_size.

3

Batch-Zeit-Normalisierung

B*T wird als Stichprobe verwendet. ddof=1 reproduziert PyTorchs Standardabweichung.

4

Identitaet als Zielmatrix

Die Loss macht C moeglichst nah an die Einheitsmatrix.

R2-Dreamer Anpassung

Die Originalidee von Barlow Twins lernt aus zwei verzerrten Ansichten desselben Bildes. Hier ersetzt die Loss den Decoder: Der Weltmodell-Zustand muss eine lineare Projektion erzeugen, die mit dem Encoder-Embedding korreliert, ohne redundante Dimensionen aufzubauen.

Deshalb passt die Loss gut zum decoderfreien R2-Dreamer-Ziel: keine Pixel rekonstruieren, sondern eine kompakte, trainingsnuetzliche Repräsentation stabilisieren.

Gradientenpfad

barlow_stop_grad=True stoppt den Gradienten auf der Encoder-Seite. Dann aktualisiert Barlow Twins vor allem Projektor und RSSM.

Mit dem CLI-Schalter --barlow_grad_to_encoder wird barlow_stop_grad=False. Das ist in deinem Code als Protocol-D-Diagnose dokumentiert, um zu testen, ob Encoder, Aggregator MLP oder VGGT zu wenig Signal erhalten.

Implementierung, fokussiert

Die Loss lebt in src/r2dreamer/representation/barlow.py und wird in representation_loss zusammen mit repval zusammengesetzt.

Wichtig fuer Paritaet: Der Kommentar im Code nennt ddof=1, weil torch.std() standardmaessig Bessel-Korrektur nutzt. Das ist eine kleine Zeile, aber fuer Cross-Framework-Vergleiche sichtbar. 
# src/r2dreamer/representation/barlow.py
feat_flat = feat.reshape(B * T, -1)
embed_flat = embed.reshape(B * T, -1)

x1 = modules["projector"].apply(params["projector"], feat_flat)
x2 = jax.lax.stop_gradient(embed_flat) if cfg.barlow_stop_grad else embed_flat

x1_norm = (x1 - jnp.mean(x1, axis=0)) / (jnp.std(x1, axis=0, ddof=1) + 1e-8)
x2_norm = (x2 - jnp.mean(x2, axis=0)) / (jnp.std(x2, axis=0, ddof=1) + 1e-8)

c = (x1_norm.T @ x2_norm) / (B * T)
invariance = jnp.sum((jnp.diag(c) - 1.0) ** 2)
redundancy = jnp.sum((c * (1.0 - jnp.eye(c.shape[0]))) ** 2)
loss = invariance + cfg.barlow_lambda * redundancy
# src/r2dreamer/config.py
barlow_lambda: float = 5e-4
barlow_stop_grad: bool = True

scale_barlow: float = 0.05

batch_size: int = 16
seq_len: int = 64

@property
def feat_size(self) -> int:
    return self.stoch_size + self.deter_size

Lesart

Beide Kurven fallen stark zu Beginn. Das ist erwartbar: Projektor und RSSM lernen schnell, die groben Encoder-Dimensionen zu treffen. Spaeter bleibt ein Plateau, weil die Loss weiterhin mit KL-, Reward-, Continue-, Actor-, Critic- und Repval-Terms konkurriert.

Der VGGT-FiLM-Run startet hoeher, weil das Encoder-Ziel eine andere, hochdimensionale 3D-Repräsentation liefert. Die absolute Zahl ist daher nicht direkt mit einer Rekonstruktionsloss oder anderen Encoder-Setups vergleichbar.

Projekt-spezifische Konsequenz: Fuer Analysen ist loss/barlow ein Diagnosesignal fuer Alignment und Redundanz, aber nicht allein ein Erfolgsmetriksurrogat. In ObjectNav muessen SPL, Success Rate, Rewards und Latent-Diagnostik daneben gelesen werden.
