Transformer Encoder Implementations
for VGGT-Token R2Dreamer

Common patterns for adding a transformer encoder on top of a frozen vision foundation model's token output — surveyed from the canonical Vaswani recipe through modern LLM-era refinements to the specific patterns that match the backbone → tokens → encoder → policy setup of R2Dreamer.

branch: feat/variant-1-aggregator-mlp · compiled 2026-05-16

TL;DR & Recommendation

What to actually build, in three paragraphs. Read this; skim the rest as needed.

Modern practice for "encoder on top of vision-backbone tokens" is a thin set of architectural choices on top of the original 2017 recipe. The mechanical core hasn't changed; the defaults have. For VGGT tokens specifically — which already carry rich geometric/positional signal from the aggregator — the encoder's job is feature refinement and (eventually) cross-modal fusion, not learning structure from scratch.

The two recipes worth considering are DETR-style (a 4–6 layer pre-norm Vaswani encoder with positional encoding re-injected at every layer) and Perceiver-IO-style (a small learned latent array cross-attends to the VGGT token sequence, then self-attends among itself). DETR is closer to your existing aggregator-MLP fast path; Perceiver IO is the right answer if VGGT emits many tokens and you want compute decoupled from token count.

if  vggt_tokens.shape[1] ≤ ~512
Start with the DETR recipe. Plain nn.TransformerEncoder with norm_first=True, batch_first=True, activation="gelu", 4–6 layers, d_model matching VGGT width (or projected to 512), 8 heads. Re-add 2D positional encoding at every layer's Q/K (you'll need to subclass the layer to do this). Append a learnable [SUMMARY] token if the policy head wants a global vector.
elif vggt_tokens.shape[1] ≥ ~1024  or  #views varies
Use Perceiver IO. 128–256 learnable latents cross-attend once to the VGGT tokens (+ optional language tokens, fused in the same KV array), then 4–6 self-attention blocks among the latents. Compute is O(N_lat · N_in) — bounded regardless of view count.
in both cases
Pre-norm. RMSNorm. SwiGLU FFN at d_ff ≈ 2.67 · d_model. Bias-free linears. Fused QKV projection. F.scaled_dot_product_attention for the attention call (auto-dispatches FlashAttention). GPT-2 residual init (1/√(2L) on output projections). Final RMSNorm after the stack. No PE if VGGT aggregator tokens already encode geometry; 2D RoPE if not.
★ Pragmatic path

Build the DETR-style encoder first — it's ~80 LOC on top of nn.TransformerEncoderLayer and slots cleanly into the existing Encoder interface in your feat/variant-1-aggregator-mlp branch. Profile, then swap to Perceiver IO only if the token count or compute budget demands it. Both encoders honor the same (tokens, mask) → tokens contract, so the swap is local.

1. Foundations

The canonical encoder block, the PyTorch API that implements it, the ~30 lines you can write from memory, and the two reference notebooks every researcher in this space has read.

1.1The canonical block

From Vaswani et al. 2017 (arxiv:1706.03762), a single encoder layer is two sublayers, each wrapped in a residual+LayerNorm. Originally published as post-norm: 

# post-norm — original 2017 formulation
x = LayerNorm(x + MultiHeadAttention(x, x, x))
x = LayerNorm(x + FFN(x))

FFN(x) = Linear(d_ff → d_model)( ReLU( Linear(d_model → d_ff)(x) ) )

The pieces, with the reason each one exists:

  • Multi-head self-attention — every token aggregates information from every other token in one step (the contrast with an RNN's sequential mixing). Multiple heads give independent subspaces for different relations.
  • Residuals — gradient highway; lets each block learn an identity perturbation instead of the full mapping.
  • LayerNorm — stabilises activations per position, independent of batch size. BatchNorm would couple sequence elements across the batch, which is wrong for variable-length sequences.
  • FFN with 4× expansion — the only nonlinearity that operates on each token independently; the per-token "thinking" step between mixing steps.

Shape convention is (batch, seq, d_model) in basically all modern code. PyTorch's historical default was (seq, batch, d_model); see §1.2.

Pre-norm vs post-norm

The original paper is post-norm. It trains poorly without careful LR warmup on deep stacks. Every modern stack (GPT-2 onward, BERT-large variants, ViT, LLaMA) uses pre-norm — LayerNorm before the sublayer, inside the residual branch: x = x + Attn(LN(x)). More stable, no warmup needed. The canonical reference is Xiong et al. 2020, "On Layer Normalization in the Transformer Architecture". In PyTorch: norm_first=True.

The two-mask convention trap

forward() takes two masks with opposite semantics for the same Boolean:

  • src_key_padding_mask, shape (B,S): True = "ignore this position" (padding).
  • src_mask (attn mask), shape (S,S) or (B·nhead, S, S): True = "mask this out", i.e. set logits to -inf. Floats are added to attention logits, so use -inf to block.

Both live in the same call. People invert padding masks constantly. Write a unit test that checks attention weights from a known padded position are zero.

When to roll your own instead of using the built-in: if you need cross-attention with multiple key sources (very relevant for a VLA — language tokens cross- attending vision tokens), register attention weights for visualisation, swap to a custom attention backend, or implement DETR-style PE re-injection. Otherwise nn.TransformerEncoder is fused and fast.

1.3The 30-line "from-scratch" block

The minimal pre-norm encoder block any practitioner should be able to write from memory: 

class EncoderBlock(nn.Module):
    def __init__(self, d_model=512, nhead=8,
                 dim_ff=2048, dropout=0.1):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.ln2 = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(
            d_model, nhead, dropout=dropout, batch_first=True)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, dim_ff),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(dim_ff, d_model),
        )
        self.drop = nn.Dropout(dropout)

    def forward(self, x, key_padding_mask=None):
        # pre-norm
        h = self.ln1(x)
        a, _ = self.attn(h, h, h,
                         key_padding_mask=key_padding_mask,
                         need_weights=False)
        x = x + self.drop(a)
        x = x + self.drop(self.ffn(self.ln2(x)))
        return x

Stack N of these for the encoder. Add learned or sinusoidal positional embeddings to x before the first block. For VGGT tokens that already carry spatial information from the aggregator, a single learned PE per token-slot is usually enough — and sometimes none at all (see §3.3).

1.4Two reference implementations to read end-to-end

Sasha Rush — "The Annotated Transformer" (2022 rewrite)

nlp.seas.harvard.edu/annotated-transformer — the entire Vaswani paper as a literate-programming PyTorch notebook. Every equation paired with the line that implements it. The 2022 update modernizes the code to current PyTorch idioms, adds type hints, fixes propagated bugs. The EncoderLayer is ~15 lines. Shows masking, sinusoidal PE, label smoothing, the Noam LR schedule — all the unglamorous machinery papers skip. Best resource for understanding every line. Less ideal for copy-paste.

Karpathy — nanoGPT and "Let's build GPT"

github.com/karpathy/nanoGPT · YouTube (2h). A full GPT in ~300 lines, ~100 for the block. Decoder (causal mask) but structurally identical to an encoder — just drop the causal mask. The clean MHA pattern with no einsum gymnastics: 

qkv = self.c_attn(x)                              # (B, T, 3D)
q, k, v = qkv.split(D, dim=2)
q = q.view(B, T, nh, hd).transpose(1, 2)          # (B, nh, T, hd)
k = k.view(B, T, nh, hd).transpose(1, 2)
v = v.view(B, T, nh, hd).transpose(1, 2)
y = F.scaled_dot_product_attention(q, k, v, is_causal=False)  # fused
y = y.transpose(1, 2).contiguous().view(B, T, D)
y = self.c_proj(y)

Notice the two efficiency wins: one fused Linear(D, 3D) instead of three separate projections, and F.scaled_dot_product_attention (PyTorch ≥ 2.0) which dispatches automatically to FlashAttention on supported GPUs. Common bugs: forgetting .contiguous() after transpose before .view(), and forgetting the 1/√d_head scale if you roll your own softmax.

2.2The Flax encoder block

The pre-norm encoder block from §1.3, rewritten in idiomatic Flax linen. Same shape contract as your existing modules: (B, N, D) → (B, N, D). 

class EncoderBlock(nn.Module):
    d_model: int = 512
    nhead:   int = 8
    dim_ff:  int = 2048
    dropout: float = 0.0

    @nn.compact
    def __call__(self, x, deterministic=True, mask=None):
        # pre-norm self-attention
        h = nn.RMSNorm(name="norm1")(x)
        h = nn.SelfAttention(
            num_heads=self.nhead,
            qkv_features=self.d_model,
            dropout_rate=self.dropout,
            deterministic=deterministic,
            name="attn",
        )(h, mask=mask)
        x = x + h
        # pre-norm FFN
        h = nn.RMSNorm(name="norm2")(x)
        h = nn.Dense(self.dim_ff, name="ff1")(h)
        h = nn.silu(h)              # or nn.gelu
        h = nn.Dense(self.d_model, name="ff2")(h)
        return x + h

Stack N of these in a parent module that loops, or use nn.scan to share parameters / save memory on long stacks.

2.3Flax-specific gotchas

  • Mask semantics — inverted vs PyTorch's attn_mask. Flax's mask uses True = keep, False = mask out — the opposite of PyTorch's src_mask. Pick one convention at the boundary and don't interleave.
  • Dropout requires an RNG. Pass rngs={"dropout": key} in model.apply(), otherwise Flax raises. PyTorch sources its own RNG.
  • Train/eval is per-call, not global. Flax has no .train()/.eval() toggle — pass deterministic=True to disable dropout at eval. Forget it once and dropout silently stays on during evaluation.
  • Init defaults differ. Flax nn.Dense defaults to lecun_normal() for the kernel and zeros for the bias. PyTorch defaults to Kaiming uniform with bias. Same order of magnitude but reproducibility tests need to know.
  • Bias-free linears. Pass use_bias=False on nn.Dense, same as PyTorch's bias=False. Your Projector module (networks.py:481) already does this.
  • @nn.compact vs setup(). Both work; your networks.py uses @nn.compact consistently — stick with it for anything you add so parameter trees stay structurally identical.

2.5Mapping to your existing VGGTAggregatorMLPEncoder

Your variant-1 encoder, distilled (src/r2dreamer/networks.py:457–478): 

# Current — networks.py:474–477
if obs.ndim == 2:                                # (B, D) — fast path
    return nn.Dense(self.embed_dim, name="proj")(obs)
if obs.ndim == 3:                                # (B, N, D) — legacy
    tokens = nn.Dense(self.embed_dim, name="proj")(obs)
    return tokens.mean(axis=1)                   # pool AFTER project

A transformer-encoder variant differs in four concrete ways:

  1. Lives on the (B, N, D) path, not the fast (B, D) path. Self-attention needs the sequence dimension. Your replay-buffer fast path of mean-pooled features is incompatible — you'd have to store the full token sequence in replay (much more disk / RAM) or recompute it from raw frames at training time.
  2. Pool last, not first. Current: mean-pool → project. Transformer: project → N×(attend + FFN) → pool (mean / CLS-token / PMA). The pooling-last order is the whole point — per-token features get enriched by cross-token context before being summarised, replacing the unweighted mean with a learned, context-dependent aggregation.
  3. ~10–100× more parameters and compute. Your Dense(D → 1024) with D ≈ 4096 is ~4M params. A 4-layer encoder of width 1024 with 8 heads and ff=4096 is ~50M params and an O(N²·d) attention per layer.
  4. Your R2MLP is already a token-wise FFN. Dense → RMSNorm → SiLU (networks.py:411–433) — exactly the FFN sublayer of the transformer block above. The transformer encoder is "alternating R2MLP-style FFNs with self-attention sublayers". Framing it that way makes the addition feel less like a rewrite and more like an insertion.
★ Worth checking before you build it

VGGT's aggregator already runs heavy cross-token attention internally over patches × views. The real question for a variant-2-encoder isn't "does the policy need attention", it's "does the policy need attention on top of an already-attended representation". Often the answer is no, and a small MLP (≈ what you have) is the right call. Design the variant comparison to test that explicitly — otherwise you're adding compute for an ambiguous win.

3. Modern Architectural Choices

What production transformers (LLaMA, GPT-J, modern ViTs) do differently from the 2017 recipe. Most of these are small per-line changes with measurable wins.

3.1Pre-norm beats post-norm

Covered in the callout above. Pre-norm puts LN inside the residual branch, so gradients flow through an identity highway. Now the default in GPT, LLaMA, ViT, and PyTorch's nn.TransformerEncoderLayer(norm_first=True). Reference: Xiong et al. 2020 (arxiv:2002.04745).

Refinements: NormFormer (arxiv:2110.09456) adds extra LN after attention and inside the FFN to fix gradient-magnitude mismatch. Sub-LN / Magneto / Foundation Transformers (arxiv:2210.06423) places LN on both sides of every sublayer for very deep / multimodal stability.

3.2RMSNorm

Drop the mean-centering step and the learnable bias; normalize purely by the root-mean-square of activations with a single gain vector: \( \text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \varepsilon}} \odot g \). Roughly 10–30% faster than LayerNorm with no measured quality loss. Default in T5, LLaMA 1–3, Gemma, Mistral, Qwen. Reference: Zhang & Sennrich 2019 (arxiv:1910.07467).

3.3Position encoding evolution

Sinusoidal / learned absolute

Original recipe. Learned absolute (BERT/ViT) is simple but doesn't extrapolate beyond trained sequence length.

RoPE — Rotary Position Embedding

Rotates Q and K by position-dependent angles such that the dot product encodes relative position. Standard in LLaMA, PaLM, Qwen, GPT-NeoX, and the basis for length-extrapolation tricks like NTK and YaRN. Reference: Su et al. 2021, "RoFormer".

ALiBi

Static linear bias added to attention logits proportional to token distance. No learned parameters, excellent extrapolation. Used in BLOOM and MPT. Reference: Press et al. 2021, "Train Short, Test Long".

Vision-specific

2D RoPE (factorized over H and W axes) is now standard in modern ViTs — EVA-02 (arxiv:2303.11331), DINOv2 variants. Swin (arxiv:2103.14030) uses a learned 2D relative-position-bias table.

★ For VGGT tokens specifically

The VGGT aggregator injects camera intrinsics + extrinsics + patch geometry into the tokens themselves. Adding another PE on top often hurts. Many recent 3D pipelines omit positional encoding on geometry-aware tokens and let the backbone's spatial signal carry through. Try with and without; default to without.

3.4FFN: ReLU → GELU → SwiGLU

SwiGLU and GeGLU are gated FFN variants: \( \text{FFN}(x) = \big(\text{Swish}(x W_g) \odot (x W_u)\big) W_d \). Three projections instead of two, consistent wins at equal compute on language benchmarks. Used in PaLM, LLaMA, Mistral, Gemma. Reference: Shazeer 2020, "GLU Variants Improve Transformer".

Sizing rule: vanilla FFN uses d_ff = 4 · d_model (2 matrices). SwiGLU has 3 matrices, so to keep parameter count constant the convention is d_ff = (2/3) · 4 · d_model ≈ 2.67 · d_model, rounded to a multiple of 64 or 128. LLaMA uses this exact ratio.

3.5FlashAttention

IO-aware tiled attention kernel that fuses the softmax and avoids materialising the \(N \times N\) attention matrix in HBM — 2–4× faster wall-clock, much lower memory, exact (not an approximation). References: Dao et al. 2022 (arxiv:2205.14135), FlashAttention-2 (arxiv:2307.08691).

In PyTorch you don't have to install anything: just call torch.nn.functional.scaled_dot_product_attention(q, k, v). It auto-dispatches to FlashAttention / memory-efficient / math backends depending on dtype and GPU. This is the single highest-leverage change in a hand-rolled encoder.

For very long token sequences: sliding-window attention (Mistral 7B, arxiv:2310.06825) — each token attends to a local window of W tokens, making attention linear in sequence length. Useful when tokens have spatial locality (relevant for dense VGGT patches over many views).

3.6Small but impactful details

  • Bias-free linear layers. LLaMA, PaLM and most modern LMs drop biases on all nn.Linear and on LayerNorm. Negligible quality cost, slightly faster, more stable in fp16/bf16. Pass bias=False. Reference: PaLM arxiv:2204.02311, §2.
  • Fused QKV projection. One Linear(d, 3·d) then split, instead of three separate Linear(d, d). Fewer kernel launches, better GEMM utilisation. This is what nn.MultiheadAttention does internally.
  • Residual-scaled init. Scale output-projection (and FFN down-projection) weights by \(1/\sqrt{2L}\) where \(L\) is the number of layers, so the variance of the residual stream stays \(O(1)\) with depth. From GPT-2 §2.3, standard in nanoGPT and Megatron.
  • Final LayerNorm. With pre-norm the residual stream is never normalized on the way out, so always add one LN (or RMSNorm) after the last block before the task head. Forgotten in some early ViT clones — it matters.

4. Encoders for Vision-Backbone Token Sets

The pattern most directly relevant to R2Dreamer: frozen vision backbone → token sequence → ENCODER → policy head. Five canonical recipes, ranked by relevance.

4.1ViT — the [CLS]-token pattern

Dosovitskiy et al. 2020 (arxiv:2010.11929). Mechanism: image → 16×16 patches → linear projection → add learnable 1D positional embeddings → prepend a learnable [CLS] token → N×(MHSA + MLP + LayerNorm) → use the [CLS] output as the set-level summary.

When to use: when you want a single aggregated token for the policy head and a well-understood encoder behind it. The [CLS]-prepend trick is the cleanest "summary token" pattern in the literature.

Reference impl: timm's VisionTransformer. 

x = torch.cat([cls.expand(B,-1,-1), vggt_tokens], dim=1) + pos_embed
x = nn.TransformerEncoder(layer, N)(x)
summary = x[:, 0]

4.2DETR encoder  ★ closest architectural analog

Carion et al. 2020 (arxiv:2005.12872). Mechanism: CNN backbone → flatten the H×W feature map to HW tokens → add fixed 2D sinusoidal PE at every encoder layer's Q/K (not just to the input) → 6-layer plain Vaswani encoder → decoder cross-attends with learned object queries.

★ Key insight

The encoder itself is vanilla. DETR's contributions are (a) a 2D sin-cos PE that respects the spatial grid and (b) re-injecting PE into Q/K at every layer, so positional information doesn't get washed out as features mix. If VGGT aggregator tokens carry per-view spatial structure, this is the recipe to clone.

Reference impl: facebookresearch/detr. See models/transformer.py for the encoder and models/position_encoding.py for PositionEmbeddingSine. 

pos = PositionEmbeddingSine(d//2)(vggt_grid)          # (B, HW, d)
tokens = vggt_tokens                                  # (B, HW, d), no PE baked in
memory = detr_encoder(tokens, pos=pos)                # PE added inside each layer

DETR's custom TransformerEncoderLayer accepts src and pos separately and does q = k = src + pos inside attention while v = src. Crib that pattern verbatim — it's ~10 lines of subclass on top of nn.TransformerEncoderLayer.

4.3Perceiver IO — use this if VGGT emits many tokens

Jaegle et al. 2021, Perceiver IO (arxiv:2107.14795), building on the original Perceiver (arxiv:2103.03206). Mechanism: a small learned latent array \(L \in \mathbb{R}^{N_{lat} \times d}\) (e.g. 256×512) cross-attends to the long input once (or a few times), then performs self-attention purely on the latents. Compute decouples from input length: \(O(N_{lat} \cdot N_{in})\) cross-attention plus \(O(N_{lat}^2)\) self-attention.

When to use: VGGT outputs many tokens (multi-view × per-view patches × aggregator tokens easily reaches thousands), or you want a fixed-size summary regardless of view count. Also natural for multimodal fusion — language tokens can be concatenated into the input array and cross-attended in one shot.

Reference impls: DeepMind (JAX) · lucidrains PyTorch port · HF Perceiver. 

latents = nn.Parameter(torch.randn(N_lat, d))
z = cross_attn(latents.expand(B,-1,-1),
               kv=vggt_tokens + pe)
for _ in range(depth):
    z = self_attn_block(z)
# z is (B, N_lat, d) — pass to policy or fuse with language

4.4Set Transformer

Lee et al. 2019 (arxiv:1810.00825). Two key blocks:

  • ISAB (Induced Set Attention Block) — like Perceiver's cross-attention, with \(M\) inducing points to make self-attention \(O(MN)\) instead of \(O(N^2)\).
  • PMA (Pooling by Multi-head Attention) — \(k\) learned seed vectors attend over the set to produce \(k\) summary tokens. k=1 gives a single set embedding.

When: tokens have no natural positional structure (true permutation-invariance desired). Probably not your case — VGGT tokens have view/patch identity — but PMA is a clean alternative to [CLS] pooling for the policy head, and worth knowing. Reference impl: juho-lee/set_transformer.

4.5Slot Attention

Locatello et al. 2020 (arxiv:2006.15055). \(K\) randomly-initialised slot vectors compete (softmax over slots, then GRU update) to bind to objects in the input — iterative cross-attention with a normalization that enforces a partition.

When: you explicitly want object-centric decomposition (one slot per graspable object) for interpretability or downstream symbolic reasoning. Overkill for plain policy learning — the inductive bias is strong and training is finicky. Mention only if R2Dreamer needs object grounding. Reference impls: Google Research · lucidrains PyTorch port.

5. A Concrete 2026 Recipe

Synthesizing §1–4 into the encoder you'd actually drop into R2Dreamer.

VGGT-Token Encoder · default config
  • Architecture: 4–6 encoder blocks, DETR-style PE re-injection. Final RMSNorm.
  • Width: d_model = VGGT token width (or project to 512).
  • Heads: 8 (or whatever divides d_model evenly into 64–96-dim heads).
  • Norm: Pre-norm + RMSNorm. norm_first=True if using the PyTorch built-in.
  • Activation: SwiGLU at d_ff ≈ 2.67 · d_model, rounded to ×64. If staying with the built-in, GELU at d_ff = 4 · d_model.
  • Attention call: F.scaled_dot_product_attention (auto-FlashAttention).
  • Linear layers: bias=False. Fused QKV (Linear(d, 3·d)).
  • Position encoding: none if VGGT aggregator carries geometry; otherwise 2D sin-cos PE re-injected at every layer (DETR pattern).
  • Init: output and FFN-down projections scaled by \(1/\sqrt{2L}\) (GPT-2).
  • Pooling for policy: learnable [SUMMARY] token (ViT style) or PMA (Set Transformer style). PMA generalises better if you eventually want multiple summary tokens (e.g. one per object).

The smallest working version uses PyTorch's built-in everything, no custom blocks: 

class VGGTEncoder(nn.Module):
    def __init__(self, d_model, nhead=8, depth=4):
        super().__init__()
        layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead,
            dim_feedforward=4 * d_model,
            dropout=0.0, activation="gelu",
            batch_first=True, norm_first=True,
        )
        self.encoder = nn.TransformerEncoder(layer, num_layers=depth)
        self.summary = nn.Parameter(torch.zeros(1, 1, d_model))
        self.final_norm = nn.LayerNorm(d_model)
        nn.init.trunc_normal_(self.summary, std=0.02)

    def forward(self, vggt_tokens, key_padding_mask=None):
        B = vggt_tokens.size(0)
        x = torch.cat(
            [self.summary.expand(B, -1, -1), vggt_tokens], dim=1)
        if key_padding_mask is not None:
            pad = torch.zeros(B, 1, dtype=torch.bool,
                              device=vggt_tokens.device)
            key_padding_mask = torch.cat([pad, key_padding_mask], dim=1)
        x = self.encoder(x, src_key_padding_mask=key_padding_mask)
        x = self.final_norm(x)
        return x[:, 0], x[:, 1:]   # summary, per-token

Returns both the summary token (for the policy head) and the per-token outputs (kept available for downstream language cross-attention). This is the right place to start — instrument it, measure throughput against your aggregator-MLP fast path, then iterate by swapping in DETR-style PE re-injection or SwiGLU FFN as needed.

What to measure first

Before optimising the architecture, measure (a) end-to-end token count emitted by VGGT for a representative scene, (b) wall-clock of the encoder forward against your current aggregator-MLP, (c) gradient flow into the encoder (norm per layer) to confirm pre-norm is doing its job. The choice between "small DETR-style" and "Perceiver IO" hinges on (a) and (b); architectural detail tuning is wasted before then.

6. Curated Learning Resources

Hand-picked, no-fluff. If a resource has known issues — outdated, too superficial, too deep for the goal — that's called out.

6.1 YouTube

  • Karpathy — "Let's build GPT: from scratch, in code, spelled out" ★ Essential. Builds a decoder-only transformer from torch.zeros upward in ~2 hours. Concepts transfer directly to encoders (drop the causal mask). The single best video for internalizing attention as code, not math.
  • 3Blue1Brown — "Attention in transformers, visually explained" Best visual intuition for QKV that exists. ~26 min. Watch with Karpathy, not instead of.
  • Umar Jamil — "Coding a Transformer from scratch on PyTorch" ~3 hours, encoder-decoder (translation). Complements Karpathy by being explicitly encoder-focused. His LLaMA/Mistral-from-scratch videos are also superb.
  • Yannic Kilcher's paper reviews — Attention Is All You Need · ViT · DETR Worth it specifically because your stack is vision + cross-attention. Skip his newer rant-style videos.
  • Stanford CS25 — "Transformers United" Uneven quality. Cherry-pick: Vaswani's original talk, Hinton, anything on multimodal. Skip the corporate-hype talks.

6.2 Blogs

  • Jay Alammar — "The Illustrated Transformer" Still THE starting point. 30-minute read. Every transformer diagram you've ever seen either came from here or is worse than the one here.
  • Lilian Weng — "The Transformer Family Version 2.0" Survey of every meaningful variant since 2017 — sparse, linear, long-context, RoPE, etc. Reference material, not a tutorial. Bookmark.
  • Harvard NLP / Sasha Rush — "The Annotated Transformer" (2022) The paper, line by line, as runnable PyTorch. Worth doing once end-to-end as an exercise.
  • Sebastian Raschka — "Understanding and Coding Self-Attention, Multi-Head, Cross-Attention, Causal-Attention" ★ The clearest exposition of cross-attention you'll find online. Directly relevant to VLA fusion.
  • HuggingFace NLP Course Skim only. Too API-focused for someone implementing from scratch, but the encoder/decoder/seq2seq taxonomy chapter is a clean reference.

6.3 Books

  • Sebastian Raschka — "Build a Large Language Model From Scratch" (Manning 2024) · code repo ★ This is the book for your position. Ch. 3 builds attention from scratch (self → causal → multi-head). Ch. 4 a full GPT. Every chapter ships a working notebook.
  • D2L.ai — "Dive into Deep Learning" Ch. 11 Free, with runnable PyTorch. Best for the math of attention done rigorously. Use as a reference, not cover-to-cover.
  • Bishop & Bishop — "Deep Learning: Foundations and Concepts" (2024) Free PDF on the site. Ch. 12 (Transformers) is the cleanest mathematical treatment in print. Use when you need to write the math section of your thesis.
  • Tunstall, von Werra, Wolf — "NLP with Transformers" (O'Reilly 2022) HuggingFace-centric, dated post-LLM-era. Useful if you'll lean on HF; skip otherwise.
  • Denis Rothman — "Transformers for NLP" (Packt) Skip. Raschka covers the same ground better.

6.4 Reference codebases

  • karpathy/nanoGPT ~300 LOC, hackable, the canonical minimal transformer. Read model.py once.
  • lucidrains/x-transformers Every transformer variant (RoPE, ALiBi, GLU variants, register tokens, cross-attention). Steal the encoder-with-cross-attention patterns directly for your VLA fusion.
  • facebookresearch/detr ★ The encoder-on-top-of-backbone pattern. Architecturally closest to a 3D VLA fusion encoder. Required reading.
  • lucidrains/perceiver-pytorch Latent-bottleneck cross-attention pattern. Highly relevant if VGGT token count is large.
  • timm — VisionTransformer · facebookresearch/dinov2 ViT reference. timm's is the cleaner read; DINOv2 shows the register-token trick that's now standard.
  • huggingface/transformers Production reference. Read models/vit/modeling_vit.py and models/detr/modeling_detr.py specifically — skip the framework scaffolding.

6.5If you have one weekend — minimum viable set

  1. Video — Karpathy "Let's build GPT": builds the intuition-via-code that everything else assumes you have.
  2. Blog — Raschka on self / multi-head / cross-attention: the cross-attention explanation Karpathy doesn't cover, and the exact pattern you need for VLA fusion.
  3. Code — facebookresearch/detr: the closest architectural analog to what you're building. Read models/transformer.py and models/detr.py.
