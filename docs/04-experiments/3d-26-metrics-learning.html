🗺 The big picture in one paragraph

You collected a buffer of 400 k transitions from a CNN-baseline policy on HM3D ObjectNav (sub-issue 3D-25). For each frame, you ran VGGT once and stored two different feature readouts side-by-side: WP/CP (4116-d) and Aggregator MLP (3072-d). Then you trained R2Dreamer — a recurrent latent world model — offline from that buffer, with one fixed config and three seeds per variant. The question is: which readout should feed the expensive 42 h end-to-end RL run?

To answer it, you need to read held-out metrics that compare the two trained world models. The metrics measure different things — and not all of them are directly comparable across variants. That's the source of the current decision paralysis: Aggregator wins some, WP/CP wins others, and it's not obvious which "wins" matter.

🔀 What's actually different between the two variants

WP/CP — 4116-d

What it is: Concatenation of World-Patch and Camera-Patch tokens from VGGT, flattened/pooled into a single 4116-d vector.

Inductive bias: Preserves per-patch geometric structure. Each dimension corresponds to something explicit — a patch position, a depth bin, etc.

What it should be good at: Anything that depends on where in the image the goal object is — reward shaping, success detection.

Aggregator MLP — 3072-d

What it is: An MLP head that pools the VGGT trunk's tokens into a learned 3072-d summary vector. Pretrained by VGGT's authors for a different downstream task.

Inductive bias: Spatial structure is dissolved into a learned semantic summary. Closer to "what's in the scene" than "where in the image".

What it should be good at: Modeling what changes between frames at a holistic level — dynamics, scene transitions.

🎲 Hypothesis (before looking at results): WP/CP should win reward-related metrics (it preserves goal-localization), Aggregator should win dynamics-related metrics (semantic summaries change more predictably between frames). This is roughly what the data shows.

🧠 What R2Dreamer actually learns — the RSSM in 90 seconds

R2Dreamer is a DreamerV3-style RSSM world model. Skip this section if you already know RSSMs.

At each time step, the model maintains two pieces of state:

  • $h_t$ — deterministic hidden state (a GRU cell, $h_t = f_{\text{GRU}}(h_{t-1}, s_{t-1}, a_{t-1})$). This is the "running summary" of the trajectory so far.
  • $s_t$ — stochastic categorical state (32 categoricals × 16 classes in this config). This is the "snapshot guess" of what's happening right now.

Two probability distributions over $s_t$ are estimated each step:

  • Prior $p_\theta(s_t \mid h_t)$ — what the model predicts $s_t$ to be, using only the past. This is the "imagination" distribution.
  • Posterior $q_\phi(s_t \mid h_t, z_t)$ — what the model thinks $s_t$ is, given the past and the actual observation $z_t$. This is the "perception" distribution.

A well-trained world model has prior ≈ posterior — i.e. it can predict what the next frame's latent will look like before seeing it. That gap is exactly what the dyn and rep KL losses penalize.

🔑 Once trained, the RSSM can "imagine" trajectories without seeing observations: sample $s_t \sim$ prior, roll the GRU forward, sample $s_{t+1} \sim$ prior, etc. This is how Dreamer trains its policy — by rolling imagined trajectories through the world model and computing rewards from the reward head.

⚖️ Comparability matrix — which metrics can you actually rank on?

MetricApples-to-apples across variants?Why / why not
k-step rollout MSE ⚠️ Mostly comparable, with a caveat Both predict next-step features against the same action sequence. Apples-to-apples within each variant's own feature space, but absolute scale depends on feature variance — see the relative-MSE calculator below.
Reward MSE ✅ Fully comparable Both predict the same scalar reward against the same stored reward array. Direct apples-to-apples.
Dyn / Rep KL losses ❌ Not comparable KL between two distributions defined in each variant's own learned latent space. A KL of 5 in one space ≠ a KL of 5 in another. Use only to diagnose within a variant (is training stable, is there collapse).
Posterior / prior entropy ❌ Not comparable Same reason — entropy is a property of the learned categorical distribution. Useful within-variant for collapse detection; meaningless across variants.
Barlow loss ⚠️ Suggestive only Measures off-diagonal correlation in the embedding's cross-correlation matrix. Lower = less feature redundancy. Comparable in principle (both measure correlation), but absolute scale depends on embedding dimensionality.
Encoder L2 ❌ Not comparable L2 norm of vectors of different dimensions. Use per-dim norm if you need a rough comparison.
Reconstruction NLL ❌ Not measured here This codebase has no observation decoder — there's nothing to reconstruct against. Field is structurally NaN until a decoder is added.

Bottom line: the only metrics that legitimately rank the two variants are reward MSE (clean) and k-step rollout MSE (with caveat). Everything else is for within-variant diagnostics.

🎯 The core tension — why this decision is actually hard

Look at just the two comparable metrics:

WP/CP wins reward prediction
Reward MSE: 0.344 · Aggregator: 0.494 · (Δ = −30%)
Aggregator wins dynamics fidelity
k=15 rollout MSE: 0.088 · WP/CP: 0.113 · (Δ = −22%)

Both these metrics matter for downstream RL, but for different reasons:

  • Reward MSE matters because the policy gradient signal flows through the reward head. An unreliable reward model means the actor-critic optimizes a corrupted objective. Imagine: the world model imagines a trajectory, the reward head says "+10 success bonus!" — but actually the agent didn't reach the goal. Policy learns the wrong thing.
  • k-step rollout MSE matters because the policy is trained on imagined trajectories rolled forward 15 steps. If the imagination diverges from real dynamics after 15 steps, the policy is optimized for a fantasy world. Imagine: the model imagines walking through a wall — reward head correctly says "no reward", but the planning is over impossible trajectories.
🧩 Mental model: Reward MSE measures how well the world model can score trajectories. Rollout MSE measures how well it can generate them. RL needs both. Whichever is your bottleneck determines which variant wins.

🧭 Decision framework — how to choose, once you understand

Now that you understand what each metric means and which ones are valid for ranking, here's a structured way to commit:

Step 1 — Decide which failure mode you're more worried about

  • "Policy learns wrong objective" → reward MSE matters more → pick WP/CP
  • "Policy plans in fantasy land" → rollout MSE matters more → pick Aggregator

Step 2 — Sanity check with priors

  • HM3D ObjectNav has a sparse reward (success bonus +10, step penalty −0.01). Sparse rewards are hard to predict regardless of encoder. So reward MSE differences may be more about "which encoder captured the goal cue" than overall capability.
  • 15-step horizon is the imagination horizon used by R2Dreamer's actor-critic. Errors past k=15 don't directly affect training — but errors at k≈15 strongly do.

Step 3 — Estimate the cost of getting it wrong

  • Wrong choice costs ~42 h GPU. Re-running both is ~84 h.
  • If you're 60/40 leaning one way, the expected value of running both is < 42 h × 40% = 16.8 h "saved" in regret terms, against 42 h spent. Commit if your confidence is ≥ ~60%.
  • If you're 50/50, running both is the right move.

Step 4 — Cross-check with the external (PyTorch) baseline

3D-46 is running an external PyTorch R2Dreamer baseline with WP/CP. If that shows a different ordering, the offline JAX result may be implementation-specific and the decision needs to wait.
