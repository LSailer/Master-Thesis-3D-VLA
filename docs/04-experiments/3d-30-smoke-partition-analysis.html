Why dev_gpu_h100 crashes (hypothesis)

habitat_sim renders observations using an EGL OpenGL context bound to the CUDA device. JAX then runs XLA kernels on the same GPU. The 14 successive cuda_timer warnings — JAX's delay kernels failing to get a clean measurement window — strongly suggest the H100 on uc3n082 has a configuration (likely a MIG slice, driver mode, or shared multi-tenant policy) that prevents habitat's EGL context from coexisting with JAX's CUDA context. The legacy smoke script's comment confirms this is a known issue:

# Smoke for the L1-L4 VGGT submission set, run on the SAME partition as
# production (gpu_h100) to validate the actual deployment path. The prior
# dev_gpu_h100 smoke aborted in habitat_sim's OpenGL renderer during
# prefill — possibly partition-specific.

A. Switch smoke to gpu_h100 in _base.yaml

Recommended

Match the proven-working legacy smoke. One commit, two lines.

scripts/slurm/configs/_base.yaml
 smoke:
-  partition: dev_gpu_h100
+  partition: gpu_h100
-  time: "00:30:00"
+  time: "00:45:00"
   args:
     steps: 1500
     prefill: 500
     checkpoint_every: 1000000
     seed: 42
+    log_every: 50
Pros
  • Aligns with legacy smoke that already works
  • Zero code risk, smallest diff
  • Smoke validates the same GPU class prod will use
Cons
  • Smoke may queue longer (prod queue, not dev QoS)
  • Slightly more cluster time used

B. Keep dev_gpu_h100, add JAX memory env vars

Try to reduce JAX/habitat CUDA contention by capping JAX's GPU memory and disabling preallocation.

scripts/slurm/launch.py — render_sbatch() smoke branch
   if mode == "smoke":
       lines.extend([
           "set -euo pipefail",
           "",
           "export WANDB_MODE=offline",
           "export PYTHONFAULTHANDLER=1",
+          "export XLA_PYTHON_CLIENT_PREALLOCATE=false",
+          "export XLA_PYTHON_CLIENT_MEM_FRACTION=0.7",
           "",
       ])
Pros
  • Keeps the fast dev queue if it works
  • Useful workaround for shared GPUs in general
Cons
  • Doesn't actually fix EGL/driver-level issues
  • Adds env vars to smoke only, prod stays different
  • Costs another 30-min cycle to re-test

C. Document the limitation, ship as-is

Keep dev_gpu_h100 in the config but document that it doesn't work for VGGT+habitat workloads. Update README to recommend overriding to gpu_h100 per-variant.

Pros
  • No further iteration before merging
  • dev partition could still work for non-habitat scripts
Cons
  • Default smoke command is broken for the only variant we have
  • Burdens the user with knowing the workaround
  • Will catch out future contributors
