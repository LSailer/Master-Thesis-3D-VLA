VGGT → RSSM token aggregation

Reducing $N{=}1371$ VGGT tokens of dim $D{=}1024$ into a compact world-model input

The problem. Your VGGTAggMLP currently maps the full token sequence by flatten-then-linear: $$ \mathbb{R}^{N \times D} \xrightarrow{\text{flatten}} \mathbb{R}^{ND} \xrightarrow{W} \mathbb{R}^{D}, \quad W \in \mathbb{R}^{D \times ND} $$ With $N{=}1371,\ D{=}1024$ that is $W \in \mathbb{R}^{1024 \times 1{,}403{,}904}$ ≈ 1.44 B parameters in a single layer (not 1 M — the cost is much worse than you stated). This layer dominates the model, won't learn from the data you have, and breaks the inductive bias of the patch grid.

VGGT-specific context

VGGT (built on DINOv2 ViT-L, 14×14 patches on 518×518 images) emits per frame:

  • 1 CLS + 4 register + 1 camera token (≈6 summary tokens)
  • ≈1369 patch tokens on a $37{\times}37$ spatial grid

Total ≈ 1374, matching your 1371. The CLS / register / camera tokens are real learned summaries — useful as queries or shortcuts, not just discardable.

Five candidate aggregators

1. Attention pooling with a single learned query recommended

Params (D=1024): ~3.15 M  ·  Output: $\mathbb{R}^{D}$  ·  Inductive bias: set-attention

One learned query $q \in \mathbb{R}^{1 \times D}$ (or initialised from VGGT's CLS) cross-attends to all $N$ tokens:

$$ z \;=\; \mathrm{softmax}\!\left(\tfrac{q K^\top}{\sqrt{d}}\right) V, \quad K, V = X W_k,\ X W_v $$ 
q = nn.Parameter(torch.randn(1, 1, D))   # or init from CLS
attn = nn.MultiheadAttention(D, heads=8, batch_first=True)
z, _ = attn(q.expand(B, -1, -1), tokens, tokens)   # (B, 1, D)
ProsTiny vs. naive (~3 M); same parameter count gets you a learned soft selection over patches; used in CoCa, SigLIP-2, Set Transformer's PMA; well-suited to noisy ObjectNav scenes where only a subset of patches matter.
ConsCollapses to a single vector — loses spatial layout you might want for navigation. Init matters: random query trains slower than CLS-initialised.

2. Perceiver resampler / Q-Former with $K$ latents strong alternative

Params (K=8, D=1024): ~8–9 M  ·  Output: $\mathbb{R}^{K \times D}$  ·  Inductive bias: learned multi-slot summary

$K$ learned latents $L \in \mathbb{R}^{K \times D}$ cross-attend to tokens, then 1–2 self-attention layers refine them:

$$ L^{(\ell+1)} \;=\; \mathrm{SelfAttn}\!\big(\mathrm{CrossAttn}(L^{(\ell)},\ X)\big) $$

Output is a short sequence; you can feed it to the RSSM as $K$ time-steps (DreamerV3 already handles sequences) or concatenate. Precedents: Flamingo Perceiver Resampler, BLIP-2 Q-Former.

ProsPreserves multiple "views" of the scene (object, free space, distractors). Strong empirical track record in VLM literature. Modular — $K$ is a clean ablation knob.
Cons2–3× the params of #1. If you flatten output for RSSM (16 K → 1 K linear = 16 M params), you re-introduce the original problem. Treat the $K$ latents as a sequence instead.

3. Multi-pool concat: [CLS, mean, max] + Linear baseline you must run

Params: ~3.1 M  ·  Output: $\mathbb{R}^{D}$  ·  Inductive bias: none beyond pooling

$$ z \;=\; W\big[\,\mathrm{CLS};\ \tfrac{1}{N}{\textstyle\sum_i} x_i;\ \max_i x_i\,\big],\quad W \in \mathbb{R}^{D \times 3D} $$ 
cls = tokens[:, 0]
mean_p = patches.mean(dim=1)
max_p, _ = patches.max(dim=1)
z = linear(torch.cat([cls, mean_p, max_p], dim=-1))   # 3D → D
ProsZero attention machinery. 10 lines. Pool Me Wisely (2025) finds mean often matches/beats CLS for global tasks; max captures salient regions. If this is within 5 % of #1/#2, ship it.
ConsNo learned selection — every patch contributes equally to the mean. Weak when the scene is cluttered with distractors irrelevant to the goal object.

4. 2D spatial pooling on the patch grid good if locality matters

Params (4×4 → linear): ~16.8 M  ·  Params (1×1): ~0  ·  Output: $\mathbb{R}^{D}$

Reshape patches to $(B, D, 37, 37)$, apply AdaptiveAvgPool2d, optionally a small strided conv head:

x = patches.transpose(1,2).reshape(B, D, 37, 37)
x = F.adaptive_avg_pool2d(x, 4)            # (B, D, 4, 4)
z = linear(x.flatten(1))                   # 16384 → 1024
ProsPreserves coarse spatial layout — useful for navigation (left/right/ahead). Drop-in replacement for the CNN encoder DreamerV3 normally uses. Cheaper variant: 2-layer strided conv, ~2 M params.
ConsThrows away the long-range mixing VGGT already did. The big final linear (16 M) brings back parameter bloat. Pool to 1×1 + linear is cheap but equivalent to mean pooling.

5. Token merging (ToMe) / top-k selection skip for thesis

Params: ~0  ·  Output: reduced sequence, then pool

Score patches by similarity to CLS, keep top-$k$ (e.g. 64), then mean-pool. ToMe (Bolya 2023) merges similar tokens progressively without retraining.

ProsAlmost free in parameters. Active research direction for VLAs (AToM, EvoPress reduce OpenVLA 256 → 16 tokens).
ConsLess proven for control / world models. Adds scope to the thesis without a clear ObjectNav win. Hard to ablate cleanly.

What similar work does

  • DINO-WM (NeurIPS '24): keeps all patch tokens, predicts patch-level dynamics. Argues pooling to a single vector loses what manipulation needs. Strong case for not aggregating if the RSSM can take a token sequence.
  • R3M / VC-1: global pool to one vector — works fine for short-horizon control.
  • OpenVLA / RT-2 / π0: keep the full 256–729 token sequence and feed into an LLM. They have the parameter budget; you don't.
  • Naive linear (your current setup): strictly worse than option 1 — same parameter scale, no inductive structure.

Concrete plan for the thesis

  1. Baseline first (1 day): CLS + mean + max + Linear → method 3. If results are within ~5 % of fancier methods, that's a defensible main result.
  2. Main proposal: Single-query attention pooling (method 1) with the VGGT CLS token as the initial query, not random init. ~3 M params, strong inductive bias, easy to motivate.
  3. Ablation / stretch: Perceiver resampler with $K{=}8$ (method 2), feed the 8 latents to RSSM as an 8-step input. Compare to #1 single-vector.
  4. Skip ToMe and pure spatial conv unless #1 + #2 underperform — they add experimental scope without obvious ObjectNav wins.

All three share the same input pipeline and only the aggregator differs, which makes a clean ablation table for the thesis.
