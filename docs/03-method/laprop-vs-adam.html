LaProp vs Adam — the one-line difference

Same state buffers (m, v). Different order of operations.

Adam momentum-then-normalize: the momentum buffer holds raw gradients, divided by √v only at update time.
LaProp normalize-then-momentum: the momentum buffer holds already-normalized per-coordinate updates.
Step Adam LaProp
1 m = β1·m + (1−β1)·g g_norm = g / (√v + ε)
2 update = m / (√v + ε) m = β1·m + (1−β1)·g_norm
3 param ← param − lr·update param ← param − lr·m
Why it matters: when the learning rate changes (warmup, decay, restart), Adam's m still holds gradients at the old scale — the buffer has to "forget" before updates re-stabilize. LaProp's m holds normalized quantities weighted by the current effective LR, so schedule changes propagate immediately. That's why DreamerV3 (and this R2-Dreamer port) uses it: RL training is non-stationary and tolerates poor warmup badly.
Ziyin, Li, Ueda (2020), "LaProp: Separating Momentum and Adaptivity in Adam."
