# Issue Tracker: Linear

Issues and PRDs for this repo live in Linear on the `3D-WM-ObjectNAV` team.
Use Linear as the canonical tracker; use GitHub pull requests as linked implementation artifacts.

## Conventions

- Create implementation issues in Linear team `3D-WM-ObjectNAV`.
- Use Linear issue keys in branch/worktree names, commit subjects, PR titles, and PR bodies.
- Link GitHub PRs back to the Linear issue when code is published.
- For experiment work, include relevant SLURM job IDs, W&B run IDs, config names, output paths, and terminal status in Linear comments.
- If Linear write tools are unavailable, prepare the exact comment or issue body for the user to paste, and say that Linear could not be updated.

## When a skill says "publish to the issue tracker"

Create or update a Linear issue in team `3D-WM-ObjectNAV`. Include acceptance criteria, non-goals, verification expectations, and any linked docs or PRs.

## When a skill says "fetch the relevant ticket"

Read the Linear issue by key, for example `3D-62`, including its description, status, labels, links, comments, blockers, and related issues.

## GitHub Relationship

GitHub is used for code review and merge state. Do not treat GitHub Issues as the source of truth unless the user explicitly asks for a GitHub issue.
When a PR exists, reconcile the Linear issue state with the live PR state before saying work is done.
