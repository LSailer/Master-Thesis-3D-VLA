1. What is "Variant 1"?

Variant 1 is one of several encoder strategies we are experimenting with for feeding VGGT visual features into the R2Dreamer world model. It is named vggt_aggregator_mlp in code.

The key idea is a fast path:

  1. Run the full VGGT aggregator (24-block alternating frame/global attention transformer) on each frame.
  2. Skip the VGGT prediction heads (world_points, camera_pose) — Variant 1 does not need them.
  3. Take only the final pre-head global aggregator tokens — a tensor of (1374, 1024).
  4. Mean-pool across all 1374 tokens to a single (1024,) vector before writing to the replay buffer.
  5. Inside the agent, project that vector through a single Dense(1024) layer into the world-model embedding space.
Why this matters. Storing all 1374 tokens per frame would make the replay buffer ~1374× larger and saturate GPU↔CPU bandwidth during sampling. Mean-pooling to (1024,) keeps the buffer small enough that we can use buffer_capacity=5000, batch_size=4, seq_len=32 on a single H100.

4. Two classes with the same name — don't get confused

There are two classes called VGGTAggregatorMLPEncoder. They sit at different layers of the stack:

ClassFileRole
specVGGTAggregatorMLPEncoder src/r2dreamer/launch/encoders.py (line 96) Encoder registry entry. Subclasses VGGTEncoder. Sets feature_kind="aggregator", disables VGGT heads, and exposes the EncoderSpec (obs_shape, render_resolution, agent_overrides).
flaxVGGTAggregatorMLPEncoder src/r2dreamer/networks.py (line 457) Flax nn.Module. The forward pass — a single nn.Dense(1024). Accepts both (B, D) (fast path) and legacy (B, N, D) (tests).
Mental model: the spec class describes what features land in the replay buffer; the Flax class describes what the agent does with them at train/inference time. The two are wired together by agent.py:_make_encoder(), dispatched on cfg.encoder_type == "vggt_aggregator_mlp".

5. Agent config overrides

Variant 1 ships with non-default agent overrides because the pooled features are small but expensive to produce:

agent_overrides = {
    "buffer_capacity": 5_000,    # tiny — VGGT extraction is the bottleneck, not memory
    "batch_size":      4,
    "seq_len":         32,
    "train_ratio":     128,      # high gradient steps per env step (small buffer)
}

Compare to the default VGGT encoder (buffer_capacity=1_000_000). The 200× reduction reflects the fact that we are recomputing rich features rather than caching cheap pixels.

8. Mental model — one paragraph

VGGT runs a heavy 24-block transformer on each 518×518 RGB frame and produces 1374 global aggregator tokens at 1024-D. Variant 1 throws away VGGT's prediction heads entirely, mean-pools those 1374 tokens down to a single 1024-D vector, stores that in the replay buffer, and pushes it through a single linear layer inside the agent to get the world-model embedding. The interesting engineering is in the compression boundary: where the JAX feature extractor hands JAX arrays off to a NumPy replay buffer. Everything before that boundary is GPU-resident; everything after is CPU-resident until the train step pulls a small (4, 32, 1024) batch back to the GPU.
